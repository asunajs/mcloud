## Go 侧十条

| # | 门禁 | 管什么 | 从哪来 |
| --- | --- | --- | --- |
| 1 | `go build $GO_PKGS` | 能编译 | Go 版 |
| 2 | `go vet $GO_PKGS` | 静态检查 —— ⚠ **≠ clippy，覆盖窄得多** | Go 版 |
| 3 | `gofmt -l ./cmd ./internal` | 格式 | Go 版 |
| 4 | `go test -race $GO_PKGS` | 测试 **+ 竞态** | Go 版 |
| 5 | `node scripts/check-go-deps.js` | Go 侧分层铁律 | Go 版 |
| 6 | `node scripts/check-filenames.js` | 文件名规则 | **复用** |
| 7 | `node scripts/check-identifiers.cjs` | 不得有真实标识 | **复用** |
| 8 | `node scripts/check-golden-vectors.cjs` | 黄金向量能算出自己 | **复用** |
| 9 | `node scripts/check-go-jsontags.cjs` | 结构体字段的 `json` tag 不许漏写 | Go 版 |
| 10 | `node scripts/check-md-tables.cjs` | markdown 表格不许比表头多格 | Go 版（**仓库级**，见下） |

> ⚠ 1–4 写的是 `$GO_PKGS` 而**不是**惯用的 `./...`：这条定义诞生于 Rust 还住在
> 本仓库的时期 —— 当时 `./...` 会去遍历 `legacy/target/`（7 GB 的 cargo 构建产物，
> 就装在那个目录里），既慢、又会在 cargo 同时改写它时撞上刚被删的临时目录而**偶发失败**。
> 2026-09-21 Rust 已剥离到同级仓库，遍历问题不复存在，但**显式包范围保留**：
> 它顺带把"只测交付物"这件事写进了定义里。理由的现版本见 `scripts/gates-go.js` 顶部。

> ⚠⚠ **只跑子集时，末尾横幅会明说"本次 N/10 条"并列出未跑的**：
>
> ```
> $ node scripts/gates-go.js fmt deps filenames idents jsontags    # pre-commit 那 5 条
> 门禁通过：fmt deps filenames idents jsontags（本次 5/10 条）
> ⚠ 未跑：build vet test golden md-tables
>   ⇒ 别把这当成"全绿"：上面这几条**这次没验**。
> ```
>
> **这是刻意的**：早先它无条件打"九项门禁全绿"，于是 `… fmt`（以及每次 `git commit`
> 的 5 条子集）也报"全绿"，把 5/9 报成 9/9 —— 而这句话正是会被抄进 `docs/status.md`
> 的那句（"门禁实况：九项门禁全绿"），抄错一次就再也说不清。
> ⚠ 同理，清单只有**一份**：`ORDER` 从 `GATE_NAMES` **派生**（见 §6.1 **#92**）。
> 抄一份进 `ORDER` 曾经让"加了门禁但默认不跑"变成**静默**事件。

**第 10 条（`md-tables`）为什么也算 Go 侧门禁** —— 它与第 6/7 条同类，是**仓库级**的
文本检查，不是 Go 专属；放在这个入口只是因为这里已经是"一条命令跑完全部"的那个入口。
它管的是一件**渲染期才会丢东西**的事：

| 判据 | 内容 |
| --- | --- |
| 拦什么 | 源码里某一行表格的**单元格数 > 表头格数** |
| 为什么必须拦 | markdown 渲染会**静默丢掉**多出来的那几格 —— 源文件里看得见，渲染出来看不见 |
| 为什么**只拦这一个方向** | "比表头**少**格"是另一类缺陷（漏写一格 / 硬换行续行），判据不同 ⇒ 混进同一条门禁会让"红了"不再指向单一原因（见 §6.1 **#127**） |
| **扫描面** | **`git ls-files --cached --others --exclude-standard '*.md'`**（跟踪 + 未跟踪未忽略）—— 与 `check-filenames.js` 同一约定。⚠⚠ **别改成手写文件清单，也别改成 fs 遍历**：前者漏掉的不自报（`THIRD-PARTY-NOTICES.md` 与 `.githooks/README.md` 就曾在清单外，见 **#131**），后者会把 `.gitignore` 特意排除的 `.workbuddy-ai/` 记忆文件重新拉进来 |
| 排除项 | 随仓库共享的**第三方技能目录**（`VENDOR_DIRS`，现为 `.workbuddy/skills/`）—— 上游内容，改了也会被下次更新覆盖。⚠ 排除**个数会打印在输出里**，不静默 |
| 拿不到清单 | `git` 失败 ⇒ **退 1 并说明原因**，不许退化成"0 个文件、通过"（反向测试：`GIT_DIR=/nonexistent`） |
| 豁免 | `docs/migration-pitfalls.md` 里 #124 那一行**自己就是受害者**（历史遗留），按**行首编号**豁免；豁免名单带**过期反向检查**（见 §6.1 **#116**） |

⚠ 写文档的人容易踩的是**写侧**：正文里想打出字面量 `|` 必须转义成 `\|`；
**`&#124;` 在行内代码里不生效**（实测过，见 **#124**）。

**6–8 刻意复用同一份脚本，不重写** —— 它们与语言无关（扫文件名 / 扫文本里的真实标识 /
独立复算向量），重写一遍等于给自己造第二份真相，而两份真相迟早分叉，
分叉那天没人知道该信哪一份。

### 第 7 条（`idents`）除了扫标识，还要守住它**自己**的三张表

它维护三样手写的东西：`ALLOWED`（允许出现的非 `199` 值，12 条）、
`VENDOR_SOURCE_PATHS`（按来源豁免的上游源码，2 条）、`TEXT_EXT`（扫哪些后缀）。
三样都是"例外清单"，而例外清单的共同毛病是**只增不减、过期不响**。
所以它自己会拦三类事：

| 拦什么 | 判据 | 为什么必须有 |
| --- | --- | --- |
| `ALLOWED` 死条目 | 每个值在**别处**（不含本文件）还出现过吗 | 表只增不减，值早就没了也没人删 |
| 豁免路径对不上 / 空豁免 | 登记的路径还在不在、那个后缀本来在不在扫描范围里 | 路径改名后豁免**静默失效**；后缀本就不扫时是**空豁免**，会让人以为"这一角处理过了" |
| 后缀覆盖不全 | 仓库里出现过的后缀必须落在 `TEXT_EXT` 或 `NOT_SCANNED_EXT` 之一 | 漏掉的后缀**不会自报**，表现是"扫了 N 个文件，通过" |

⚠⚠ **`ALLOWED` 的存活判据必须是"别处"，不能是"仓库里"**：
本脚本**自己也在扫描范围内**，而表正文就写在里面 ⇒ 把本文件的命中算进去，
**每一条都必然"还活着"**，那条检查就**恒真**（见 §6.1 **#93**）。
实测：往表里加一条仓库里根本没有的假值，仍然报"登记表 13 条、本次命中 13 条"、退 0。
⇒ 本文件自己的命中**可以报违规**（往这里抄真实值就是事故），但**不许用来证明条目还活着**。

⚠ `TEXT_EXT` 已经**漏过三次**（`.go` / `.py` / `.tsx` + `.csv`），
三次都发生在**新增一类文件**的时候。新增一类文件现在必须**显式做一次决定**：
进 `TEXT_EXT`，或进 `NOT_SCANNED_EXT` 并写理由 —— 否则退 1 并列出文件。

> 摘要行里的两个数都取**观测值**：`登记表 N 条、本次命中 M 条` —— 前者是清单，后者是事实。
> 只印清单大小就会重演 §6.1 **#92** 那个"横幅量的是清单、不是事实"的毛病。

## ⚠ 第 9 条为什么必须有：字段名的洞**只在"改坏了却不响"时露出来**

Rust 的 `#[derive(Serialize)]` 默认给 **snake_case** 字段名（`password_hash`），
而 Go 不带 tag 会输出**字段名原样**（`PasswordHash`）。同一个字段两个名字，
且**不报错** —— 只有真跑起来、另一侧读这条记录时才看得见。

这个坑在 mcloud 里犯了**三次**、分属三个模块（`CloudStats` / `User`+`Session` /
`model` 那一批），三次的共同点是：**发现它们靠的是"改坏了却不响"，不是靠测试**。
原因很具体：**往返测试用什么字段名都是绿的** —— 它只证明"自己解得回来"，
不证明"和另一侧同名"。所以必须有一条不依赖往返的守卫。

判据（见 `scripts/check-go-jsontags.cjs`）：

- **混合**（有些字段有 tag、有些没有）→ 直接失败。不可能"一半进 JSON"。
- **全都没有 tag** → 必须在白名单里并**写明理由**，否则失败。
  零 tag 有两种可能（确实不进 JSON / 整个漏写），脚本分不出来，
  所以交给白名单 —— 新增一个无 tag 的结构体必须**显式登记**，
  这就是"让它自己报出来"的那一下。
- 白名单里**对不上**的条目（结构体改名或已加上 tag）也判失败 ——
  否则名单会越攒越长、越来越没人看。

⚠ 全是非导出字段的结构体（`Error` / `enumJSON` / `phcParams` …）**直接跳过**：
`encoding/json` 本来就看不见它们，登记进白名单只会稀释信号。

两条**不可省**的替代关系，别把它们当"Rust 侧那条的等价物"：

- **`-race` 不是可选项。** Rust 里 `&mut R rng` 保证同一随机源不被并发共享 —— 那是
  **编译期**保证。Go 的 `io.Reader` 是引用语义，并发共用一个源是 data race，
  而它**不一定**让测试变红：可能只是偶发产生错误数据（签名对不上、`deviceId` 错一位），
  于是被当成"上游抽风"。`-race` 是那条编译期保证在 Go 侧的替代品。

  ⚠ **`-race` 在 Windows 上需要 cgo，cgo 需要一个 C 编译器**（`go env CC`，默认 `gcc`）。
  没有它时 `go test -race` 报 `requires cgo`，**与代码无关**，但会让 `test` 红到
  一条提交都推不出去。`scripts/gates-go.js` 因此**先探测**：`go env CC` 命不中
  就降级成不带 `-race` 的 `go test`，并在横幅、该条结果行、末尾汇总行**三处**标出
  "未跑 -race"。装上 mingw-w64 / w64devkit 后自动恢复，不用改脚本。

  降级是**有意为之且必须看得见**：一个"拦住一切"的检查最后会被 `--no-verify`
  整体绕过，连带把其余七条一起废掉 —— 那样的价值是 0。宁可少一条保证但看得见，
  不要"文档写着有、实际一次没跑"。
- **`vet` 过了不代表静态检查这关过了。** 它只覆盖"几乎肯定是错"的一小撮检查。
  补齐要引 `golangci-lint`，而那是外部依赖 —— 骨架阶段刻意零第三方依赖。
  引进来之前，**不要拿 `vet` 当 `clippy` 用**。

⚠ 两个易踩的实现细节（都已在 `scripts/gates-go.js` 里处理，改脚本时别退化）：
`gofmt -l` **退出码恒为 0**，必须自己判输出是否为空；每条门禁的输出写**单独**日志文件，
否则前面通过的门禁留下的字样会污染诊断（Rust 侧踩过这个坑）。

完整理由、逐条设计与"四条会静默降级的编译期保证"见
[`go-migration-plan.md`](./go-migration-plan.md) §5。

## 在哪里跑

两个入口，**跑的是同一组命令**：

| 入口 | 什么时候 | 覆盖面 |
| --- | --- | --- |
| `pre-commit` | 每次提交 | `filenames` `idents` `md-tables` + `fmt` `deps` `jsontags`（不需要编译的那六条；前三恒跑、后三看范围） |
| `pre-push` | 每次推送 | Go 侧**十条**全跑 |

装一次即可：`node scripts/install-hooks.js`（细节见 `.githooks/README.md`）。
Rust 侧冻结后 hook 就不再碰 cargo；Rust 仓库自己的验证方式见
[`../mcloud-rust/README.md`](../../mcloud-rust/README.md)。

> ⚠ **上面那张表在 2026-09-22 之后只算"档位"，不再是"固定清单"**，两件事同时变了：
>
> **① web 侧有了门禁（此前是零）。** `scripts/gates-web.js` 两条：
>
> | 门禁 | 命令 | 实测 | 档位 |
> | --- | --- | --- | --- |
> | `typecheck` | `npm --prefix web run typecheck`（`tsmc --noEmit`） | 1.8 s | pre-commit |
> | `build` | `npm --prefix web run build`（`vite build`，自报 250 ms 左右） | 0.8 s | pre-push |
>
> （实测 = **单跑一条** `node scripts/gates-web.js <名>` 的墙钟，含 npm 启动那截；
> 两条合计 2.4 s。数字会变，量法别变。）
>
> 分档沿用原来那句判据（**发现问题的时刻与副作用**，不是快慢）：`typecheck` 纯静态、
> 报错当场可修 ⇒ 提交档；`build` 要往 `web/dist/` 写东西，与 Go 侧 `build` 同类 ⇒ 推送档。
> ⚠ 这两条**只保证"编得出来"**：web 侧至今没有测试运行器（vitest 未装，
> 见 [`webui-code-guide.md`](./webui-code-guide.md) §12 未决项 3），
> 类型与打包都绿不等于页面跑得对。那条只能靠真机核验，别把它记成"有测试了"。
>
> **② `pre-commit` 改成按暂存范围派发**（`scripts/gates-scope.js` 分类）：
>
> ```
> *.go / go.mod / go.sum  → 追加 fmt deps jsontags
> web/** 下任何文件        → 追加 typecheck
> 恒跑，不参与派发         → filenames idents md-tables
> ```
>
> 于是"改一行 `docs/*.md` 也要过一遍 Go 工具链"和"改 `.tsx` 时五条一条都验不到前端"
> 这两件事同时没了。三条让它成立的前提，破一条就变成**净损失**：
>
> 1. **`pre-push` 不看范围，全跑**（Go 十条 + web 两条）—— 提交档省下的必须在推送前补齐。
>    ⚠ 想给 `pre-push` 也加范围派发之前，先回答"被跳过的那些由谁补"。
> 2. **`filenames` / `idents` / `md-tables` 恒跑**：脱敏那条扫的是**文本**，`.md` / `.json` 一样能
>    泄漏真实标识。按语言把它切掉，等于给最不该漏的那条开一个永远存在的洞。
>    `md-tables` 是同一个形状的第三例 —— 它扫的是**整个 `docs/**`**（不是"这次暂存的那几个"），
>    而它要拦的恰恰是"**只改文档**"那类提交；那类提交在派发下只剩恒跑这一档，
>    ⇒ 不把它放进恒跑，它**永远不会在该响的时候响**。
> 3. **分类器不确定时全跑**（拿不到暂存清单 ⇒ 最保守一档），失效方向只能是"多验"。
>
> 另外分类器自己兼了一条"**给门禁的门禁**"：派发之前先按扩展名过一遍语法 ——
> `.js` 用 `node --check`、`.sh` 与两个 hook 用 `bash -n`（2026-09-22 迁 zx 后
> 两类并存才这么分，见开头那条迁移补记），覆盖门禁脚本自己与被改的 hook。
> 抓的不是逻辑错，
> 是"引号没闭合、`fi` 少了"这类**现象恰好是门禁跑了而且绿了**的假绿。
>
> 实测（2026-09-22，反向测试）：暂存一个 `web/**` 文件 ⇒ 只跑 `filenames idents md-tables` +
> `web:typecheck`；在 `web/src` 放一个类型错误的文件 ⇒ 钩子退出码 **1**，提交被拦住；
> 删掉之后恢复绿。分类另用 `stdin` 档逐条核过（含"Go+web 同时改""只改文档""删除也算"）。
>
> ⚠ 一个已知且**不打算在这里修**的错位：范围取自暂存区，而门禁验的是工作区那一份
> （Go 侧从第一天起同处境）。部分暂存（`git add -p`）在意这一点的人要自己负责。

## 跨环境

`filenames` / `idents` / `golden` 三条脚本是**语言无关**的纯 fs / Node 遍历，
平台无关这一点在 Rust 门禁时期就刻意核过（零 `execSync` / `process.platform` /
`uname` 分支），迁移后结论不变。**bash 侧只用 POSIX + bash 3.2 就能跑的语法**
（不用 `declare -A` / `mapfile` / `${v,,}` / `&>>`）—— macOS 自带的 `/bin/bash`
永远是 3.2.57，这条是 2026-09-20 在 macOS 上实跑撞出来的，
完整事故记录见 [`../mcloud-rust/docs/dev-gates.md`](../../mcloud-rust/docs/dev-gates.md)
「macOS 首跑记录」。

### 第 6 条为什么值得单独存在

这条规则以前**只写在文档里**，于是 `web/src/pages/` 下三个 `AuthPage.tsx`
一路活到被用户点名。规则写在文档里没人执行，就会反复被违反 ——
而违反的表现极其安静：编译能过、测试全绿、界面正常，
只有下一个人加文件时"照着旁边那个写"，于是错误自我复制。

判据：按 `.` 把文件名拆成段，每段必须匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`。
Rust 源文件从来不在管辖范围 —— 那边文件名就是模块名，`mod my-mod;` 不合法，
编译器已经强制了（本仓库自 2026-09-21 起也没有 `.rs` 文件了；共用脚本里那条排除
仍留着，因为脚本两边各跑一份，在 `../mcloud-rust/` 那边它是要管的）。

豁免分三类（**不允许因为"改名麻烦"而豁免**）：

1. **生态固定名**：`Cargo.toml` / `README.md` / `SKILL.md` / `index.html` —— 工具按字面找它们；
2. **上游原样取出的证据**：`docs/capture/apiServer.js`、`test/fixtures/legacy/$meta.json`
   —— 改名会破坏"文件里能搜到的符号 ↔ 文件名"的对应，而这份素材的价值恰恰在于可逐字对照；
3. **生成物 / 依赖目录**：`node_modules` / `target` / `dist`。

新增豁免要同时满足"它属于上述三类之一"与"在脚本注释里写清属于哪一类"。

### 第 8 条是抓包侧的自检

`test/golden/*.json` 是要进版本库的产物，但"有人手工改坏一个字符"只有真算一遍才发现。
它用 Node `crypto` 独立实现算**167 条**向量，与 Go 侧**互为交叉验证** ——
一边过一边不过，说明其中一边错了。

它同时做两件别处做不到的事：

- 对**每个** golden 文件跑脱敏扫描（Rust 侧的守卫在剥离后的同级仓库 `../mcloud-rust` 里，只扫 `include_str!` 进来的那些）；
- 列出**没有任何测试读取**的向量文件
  （**当前一个都没有**：最后一份 `login-crypto-vectors.json` 于 2026-09-21
  接上消费者，见 `migration-pitfalls.md` 末尾）。

覆盖范围是**显式**的：没有校验器的段会被**打印出来**，不假装通过。

## ⚠ 偶发红：运行环境会往 `go` 的 stdout 里塞一句噪音（2026-09-21 实测）

**现象**：`deps` 这条门禁偶尔变红，报的是

```
!! internal/app 未依赖 internal/io —— 组装根必须把 IO 实现接上
!! internal/server 未依赖 internal/io —— 组装根必须把 IO 实现接上
```

**而这两个包明明依赖 `internal/io`** —— 那句话把人指向一个**根本不存在的分层问题**。

**根因**：运行环境（沙箱）有时会往 `go` 的 **stdout** 里塞一句
`Brokered program policy check unavailable`，而且**没有换行** ⇒ 它**粘到 `go list`
输出的某几行行首**。`check-go-deps.js` 原先用 `grep -xF`（**整行相等**）判依赖，
于是那个依赖「凭空消失」。同一份日志里还能看到它粘在脚本自己那几行 `ok …` 前面。

**修法**：判据从「整行相等」改成「**定界符 + 子串**」——
`deps_of` 用 `-f '|{{.ImportPath}}|'` 输出，`has_dep` 用 `grep -qF "|$1|"`。
前面粘了什么都无所谓，而 `|net/http|` 仍然**不会**命中 `|net/http/httputil|`。

⚠ **别改成裸子串**（`grep -qF "$1"`）：那会让 `net/http` 误命中 `net/http/httputil`，
纯层那条断言当场失效。

**两条验证**（都实测过）：

1. 在模拟污染（每行行首加那句噪音）下，**旧判据找不到 `internal/io`**、新判据找得到，
   且新判据仍不把 `net/http` 与 `net/http/httputil` 混起来；
2. 往纯层 `internal/exec` 里注入 `_ "net/http"` ⇒ 门禁仍然报出
   `!! internal/exec 依赖了 net/http —— 违反 IO 隔离约束`（**精确性没有丢**），还原后转绿。

> 📌 这条属于"**偶发、且把人指向错误方向**"的红 —— 比门禁缺失更危险的那一类
> （见 §6.1 与 `scripts/gates-go.js` 顶部那条 `./...` 的注释）：
> 一旦学会"重跑一次就好"，防线就再也不起作用了。
> ⇒ 判据的输入**不可信**时，要么让它**准确报出**原因，要么让判据**不依赖那个形状**。
