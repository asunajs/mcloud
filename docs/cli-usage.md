## 最常用的一条：什么都不带

```bash
go run ./cmd/mcloud                          # = mcloud signin，对**全部启用**的账号各签一次
go run ./cmd/mcloud --list                   # 先看下标：1、2、3…
go run ./cmd/mcloud --account 2              # 只跑下标 2 那个
```

> ⚠ **2026-09-22 实测订正**：上面第二、三行原文写的是
> `go run ./cmd/mcloud -- --list`（**多一个 `--`**）。那个 `--` 会被 `go run` 原样传给程序，
> 而 `pflag` 把它读作"flag 到此为止"，于是后面的 `--list` 变成**位置参数、被静默忽略** ——
> 结果**不是**"列出账号"，而是**直接跑了一次签到**（实测：打出的是签到报告、余额 +3，
> 全程不报任何错）。用编译好的二进制复现同样如此（`./mcloud -- --list`），
> 所以这与 `go run` 无关，是 `--` 本身的语义。**正确写法就是不加 `--`** ——
> `go run` 在遇到包名参数后就停止解析自己的 flag，后续参数原样交给程序
> （`go run ./cmd/mcloud --list` 与 `go run ./cmd/mcloud signin --list` 均已实测可用）。

**顶层与 `mcloud signin` 收同一套参数**，所以上面两条也可以写成
`mcloud signin --list` / `mcloud signin --account 2` —— 两种写法等价，随便用哪种。
（`mcloud --list` / `mcloud --status-only` / `mcloud --json` / `mcloud --db <路径>`
全都成立；实现上顶层那个 `SigninArgs` 与子命令里的**是同一个结构体**，
默认值与互斥关系只有一份定义。）

不带子命令就是**跑签到**，一个参数都不用给 —— 对齐旧项目 `mcloud-sign` 的用法。
账号用**下标**指代（不是掩码 id）：`账号 1` / `账号 2`，与旧项目的日志语义一致。

一个账号失败**不会**让其余账号停下，最后用非零退出码统一报"有几个失败"
（定时任务靠它判断这次到底有没有全部成功）。`--json` 时单账号给**对象**、
多账号给**数组**，进度行一律走 `stderr` —— 所以 `mcloud --json | jq` 是安全的。

## 子命令一览

| 子命令 | 作用 |
| --- | --- |
| `user init` / `user list` | 建首个管理员（网页端要用，也是历史账号的认领触发点）/ 看看有哪些人 |
| `login qr` | 扫码登录移动云盘账号：终端出码，手机扫（`--qr-out` 可另存一张图片） |
| `login sms` | 短信验证码登录：发码 → 输验证码。被风控要求滑块时**自动过**（缺口位置由服务端加密下发，见 `logout-sms-login.md` §2.2.1）。⚠ `--client app` 那个"自动过"是**借 PC 端那套**取题与编码、换 App 的头发出去（围魏救赵）；App 自身的滑块**未实现自动化**，真机走的仍是开 WebView 由 H5 发码那条（见 `capture/app-sms-login-samples.txt` §2.2 的澄清） |
| `auth refresh` | 到期前向上游换新 token，**覆盖**库里那一套凭据（`authorization` / `jwt_token` / `accounts.auth_expire`，其余列不动）。端别由库里那串 auth 的第一段决定（`pc` 走 PC 客户端头、`mobile` 走 App 头），**不是**参数。`--account` 或 `--all`（后者只碰启用中的）、`--lead-days`（默认 7，**只管批量那条路**）、`--force`（**到不到点都刷**，越过提前量，与 WebUI 那枚按钮同语义）、`--platform` 仅 PC 那一支要。⚠ 不自动重试，且 PC 那一支**尚未实测** —— 证据分档与判据见 [`auth-refresh.md`](./auth-refresh.md) |
| `migrate` | 把旧项目 mcloud-sign 的数据迁移到 SQLite（`--dry-run` 预演） |
| `signin` | 签到（云朵中心）。**不带任何参数就是对全部启用账号各签一次**；`--account <下标>` 只跑一个（`--list` 查下标），`--phone <完整手机号>` 给老账号补一次。另有 `--status-only` / `--force` / `--json`。**纯协议**，不开浏览器、不开 WebView；成败只看回查 `infoV3`（见 [`status.md`](./status.md)） |
| `live-room` | 直播口令 → 抽小红花。**只在主播开播的那几小时里有效**：先"开门"（查有没有在播的官方直播间），再听弹幕收口令，最后逐个口令抽花。`--kouling-only` 只听不投（**只读**，一个口令都不投）；`--skip-kouling --codes <口令>` 跳过收集只投手工口令。⚠ `draw` 是**写操作**（会动**这个账号**的兑换状态；口令本身全场通用，投过不影响别人） |
| `smid show` / `reset` / `refresh` | 看每个账号绑定的**设备特征**（cMPassport 风控那套，旧项目拿它的结果当请求头 `deviceid` 发）、`reset` 换一个（旧的 `deviceId` 当场作废，`--report` 顺手再上报）、`refresh` 不换特征只再上报一次。输出**只有摘要**：UA 与 `canvas` 识别位不落终端。⚠ 本项目目前**还没有任何请求发这个头**，取值的那一半已就位（见 [`client-profiles-fingerprint-and-landing.md`](./client-profiles-fingerprint-and-landing.md) §5.4 ③） |
| `fixture extract` | 从 HAR 流量包抽取脱敏 fixture（用于离线回放）。脱敏有残留则 fail closed，拒绝写出 |
| `capabilities` | 打印能力注册表（`--json` 与 `GET /api/capabilities` 同形状） |
| `version` | 打印版本与运行时信息（`--json` 与 `GET /api/version` 一致） |

## 签到（`signin`）—— 七个要记住的

链路：**换 SSO token → 取服务端时间戳 → 签名建会话 → 查 `infoV3` → `startSignIn` → 回查 `infoV3`**。
全程纯协议、无浏览器、无 WebView（协议与坑见 `capture/app-signin-samples.txt`）。

### 1. 成败只看回查 `infoV3`

`startSignIn` 的 `todaySignIn` 是调用**前**的快照 ——
实测 `todaySignIn:false` 的那次恰恰把今天签上了；只看 `code == 0` 也不行，
上游对"今天已经签过"同样回 `success`。

### 2. 账号用 `--account <下标>` 给

`--list` 查编号。

**v7 起签到只用库里存的整串 `Authorization`**（见下面第 7 条），所以正常情况下什么参数都不用给。

`--phone <完整手机号>` 只留给"库里既没有整串、也没有完整手机号"的老行 ——
用它补一次就会**记进库里**（**只记号码**，见第 7 条最后一段），下次不必再输。

### 3. 端不匹配那道闸只管"现拼"那条路

签到用整串时前缀是登录时拿到的原文，不存在配错的可能 ——
**实测（2026-09-19）`pc:` 前缀的整串在签到接口上完全有效**
（旧项目也从不区分：它的 `asign.json` 里两个账号一个 `mobile:` 一个 `pc:`，
走的是同一条签到路径）。

只有**退路**（用 `phone` + `jwt_token` 现拼）才把前缀硬编码成 `mobile`，
那时若账号是用 `--client pc` 登录的，会被明确挡下来并提示重登 ——
这个组合没实测过，宁可拒绝也不要发出去试探（失败会长得像"未登录"）。

### 4. 每次查询都会顺手记一次余额

`app.RecordCloud`：余额 → `accounts.cloud_current` + `cloud_stats` 日快照
（日增 / 周增在 `core.NextCloudStats` 里算，是纯函数）。

> ⚠ **2026-09-22 按代码订正两处**：① 上面这两处函数名当时是 Rust 路径
>   （`mcloud-app::cloud::record_cloud` / `mcloud-core::pure::next_cloud_stats`），
>   Rust 已剥离为同级仓库，落点改成本仓库的 `app.RecordCloud` / `core.NextCloudStats`。
>   ② 原文写的是 `infoV3.beforeTotal`，而 `runStatusOnly` 实落的是
>   **`status.BeanTotal`（上游 `total`）** —— `run_signin.go:631` 那条注释就是为了
>   挡住这个：`beforeTotal` 不随领取变动，记它等于让趋势图永远是一条直线
>   （`run_signin.go:645`；`beforeTotal` 这个名字现在挂在 `--raw` 的
>   `CloudTotal` 上，`signin_render.go:453-458`）。下面那段「`before` 指领取前」
>   的语义仍然成立，成立的是**上游那个字段**，不是我们落库选的那个。

注意那个 `before` 指的是**领取前**、不是"签到前"—— 签到只是打卡、云朵要另外领，
所以它签到前后**不变**，不是"签到完余额就该 +3"。

落库失败只打一句 `stderr` 警告，**不影响签到结论**
（余额是顺带采集的副产品，不该把一次成功的签到变成失败）。

### 5. 领云朵是另一个接口（`receiveV3`），而且必须带 H5 那个 `deviceId`

`--receive` 打开。实测三档（2026-09-19，只换 `deviceId` 一项）：

| `deviceId` | 结果 |
| --- | --- |
| 不带 | `615` |
| 内容错一个字符 | `614` |
| 真值 | `code=0` |

⇒ **上游校验的是内容，不只是"非空"**，"随便编一个"走不通。

⚠ 那两个码的 msg 都是"活动太火爆啦…"，会把人的思路带到"限流 / 退避重试"上，
而真实原因是**参数问题** —— 重试一万次也没用。

⚠ 这个 `deviceId` **就是 `smid` 那条线换回来的 `"B"+detail.deviceId`** ——
**本工具自己就能算（`mcloud smid refresh`），不需要浏览器、也不需要装官方 App**。

曾经记成"它是另一个东西、构造不出来（密钥未知）"，那是把两件事看混了。真相：

- 签到页的 `fp.min.js` 是**数美设备指纹**，`window.SMSdk` 是**它自己定义**的
  （所以 App 二进制里搜不到这个名字）；
- `getDeviceId()` 返回 `'B' + localStorage['SMID']`，而 `SMID` 就是它往
  `slw.h5cmpassport.com:9090/deviceprofile/v4` 上报特征后拿回的 `detail.deviceId`；
- 那套配置 —— organization / appId / RSA 公钥 / host —— 写在签到页 HTML 的
  `window._smConf` 里，与 `internal/upstream/smid.go` 的常量**逐字相同**。

守卫：`smid::tests::the_signin_page_fingerprint_sdk_is_this_same_client` —— 那是 **Rust 基准**里的测试名，
基准现已移到同级仓库 [`../mcloud-rust`](../../mcloud-rust)。
⚠ **Go 侧目前没有把这条守卫钉过来**：`test/golden/app-signin-vectors.json` 与 `crypto-vectors.json`
里存着从签到页抄下来的 `SM_ORGANIZATION` / `SM_API_HOST`，Go 侧也有同值的
`upstream.SmOrganization` / `upstream.SmAPIHost`（`internal/upstream/smid.go`），
但**没有任何一条断言把两边对上**（全仓搜不到读这两个黄金键的代码 —— `smid_test.go` 是拿常量拼期望值，
不是拿黄金值校验常量）。补一条"常量 ≡ 黄金向量"的用例即可等价还原。

⇒ 所以 `--receive` **一个额外参数都不用给**：不传 `--device-id` 时自动从库里
这个账号的 `smid_device_id` 取，库里没有就**现上报一次换一个**：

```bash
mcloud signin --account 2 --receive --cloud-type 2
```

`--device-id` 只在要做对照实验时才显式给（旧名 `--h5-device-id` 仍可用）。

⚠ 那个值末尾有**一个多余的 `=`**（89 字符 = `B` + 86 数据字符 + 2 个 padding，
规范只要 1 个）—— 那是它本来的样子，**原样透传，别"顺手规范化"**。

⚠ 顺带更正一条早先的误判：把整串 89 字符当 base64 解码会得到 65 字节、
"首字节"是 `0x05`/`0x06` —— 那个字节其实是 **`'B'` 前缀与 SMID 首字符共用了一个字节**，
既不是魔数、也没有"65 字节"这回事，真实结构是 **`'B'` + 64 字节**。

当前 `--cloud-type` 也从 `infoV3` 的 `receiveList` 里读（跑一次 `--status-only` 就会打出来）。

### 6. 复活卡 / 回馈卡是第三个接口（`receiveRevivalReward`），而且它不可逆

`--revive` 打开。H5 原话：「关闭弹窗视为放弃机会，**无法补发**」——
所以它单独一个开关、默认不开，绝不跟着签到顺手跑。

请求形状极简：`POST` + **空对象体 `{}`**，且是整页**唯一**一个
`showLoading: false` 的接口（H5 要自己画卡片弹窗）。

⚠ 它**不需要** `deviceId`（H5 定义里没有 `isDeviceId`），
但老抓包里带了个 `deviceid` 头 —— **两个证据不一致，未验证**，
所以参数留成可选：不给就照 H5 定义，给了就补那个头。

⚠ 响应里的 `totalClouds` **没有**接进余额采集：H5 文案说复活卡产出的是**AI豆**，
与 `infoV3.beforeTotal`（云朵余额）可能不是一个池子，现有实拍分不出来。

这一族**没有判活接口**，"本月还剩几次"只能发一次写请求去撞。2026-09-25 真账号撞到的
那句是 `{"code":500,"msg":"本月已领取复活卡奖励"}` —— 它**不是**运行失败：`--json` 的
`revive` 报 `ok: true` + `claimed: false` + `message`（上游原话），退出码仍是成功，
与 `--multiple` 的"本月已领过"同一档。认不出的文案仍报 `ok: false` + `error`，
不折成"没领"（判据见 `internal/upstream/app_signin_receive.go` 的 `RevivalAlreadyClaimed`）。

### 自检参数

- `--status-only`：只查不签；
- `--force`：已签也发一次 `startSignIn`，用来确认请求被上游接受；
- `--json`：给脚本 / 定时任务消费。

⚠ `--receive` / `--revive` 都是**写请求**，它们的结果也会进 `--json`
（`receive` / `revive` 两个键）—— 别把它们写成"只看不写"的开关。

### 7. `Authorization` 是整串存、整串用（schema v7）—— 不要再拆开再拼

它的形状是 `Basic base64("<前缀>:<手机号>:<authToken>")`，登录时**一次就拿到整串**，
所以 `account_state.authorization` 存的就是它**原文**，发请求时原样用出去。

旧项目 `mcloud-sign` 一直这么做（它的 `asign.json` 里 `auth` 存的就是整串），
照搬即可，没有重新发明的必要。

早先的写法是"只留第三段 token，用的时候拿手机号现拼" —— 那是**绕远路且会错**：

1. 必须凑齐手机号，缺了就只能让用户每次在命令行上补（`--phone`）；
2. 前缀被硬编码成 `mobile`，猜错**静默**发出错误的头，表现为 `90001` 未登录。

⇒ 读侧**整串优先**，`phone` 列降级成"标识"（打印、排障），**不参与拼头**；
`phone` + `jwt_token` 现拼只作为 v7 之前老行的退路。

⇒ 老行由 `migrate` 回填：`asign.json` 的 `auth` → `account_state.authorization`。

这条回填**按状态判**（"这一列空着就填"）而不是按源文件哈希判 ——
后者对已经导入过的库永远不会再跑，会让同一个版本的程序产出两种库形态。
只填空缺的语义让它幂等，于是"每次都跑"是安全的：
**重登过的新凭据不会被旧配置覆盖回去**（有测试钉住）。

> ⚠ **这一列只装「拿到的」，不装「拼出来的」。**
>
> 合法来源只有两个：登录响应里的 `auth`、旧配置里的 `auth` —— 都是原样给的。
> **本地合成的串一律不许写进去**：读侧会**优先采信**整串，
> 而整串路径**没有前缀可校验**（前缀就在串里），
> 于是一串拼错的凭据落库后会被永久当成原文使用，现象只是"忽然回 `90001` 未登录"。
>
> 典型反例正是 `--phone` 那条退路：它拼出来的前缀固定是 `mobile`，
> 拿它去补一个 `pc:` 端账号，存下去就是**永久错的**。
>
> ⇒ 所以 `--phone` **只记手机号**（那是用户给的事实），不记那次现拼的串；
> 下次照旧现拼、前缀闸照旧生效，而用户同样不必输第二遍。

## 直播口令 → 抽小红花（`live-room`）—— 只在开播那几小时里有效

```bash
mcloud live-room                       # 开门 → 听 60 秒弹幕 → 逐个口令抽花
mcloud live-room --kouling-only        # 只听不投：收口令并打印，**一个口令都不投给上游**
mcloud live-room --skip-kouling --codes "口令甲,口令乙"   # 只投手工口令，不收集
mcloud live-room --account 2 --json    # 只跑第 2 个启用账号，结构化输出
```

⚠ **这条链的时间窗是硬的**：上游那句「口令需当场直播获取才有效哦」说明从别处抄来的
口令一律不通。没开播时它不会失败，只是**没有可投的口令**（见下面"两种没有"）。

链路：**开门（`querySpecTokenV2` → `cmpassLoginByCmToken` → 两个页签的 `tabContentList`）
→ 双源收口令（WS 弹幕 + 口令发布方的小红书主页，**并发**）→ 六步链**
（`user/info` → `visitlog/journaling` ×5 → `firstParticipate/give` →
`redFlower/draw?code=…` ×N → `queryRevivalFlowers` → `user/info`）。

要记住的五条：

1. **门有两种"没有"，下一步完全不同。** 输出会分开说：
   「一间都没在播」（`LiveCount == 0`，等着）与「有 N 间在播，但没有一间是「中国移动云盘」」
   （别的主播在播，别等了 —— 实拍撞到过房间 147490「福建移动」）。
   判据是 **`status == 1` 且 `anchor.nickname` 精确等于那个固定昵称**两个条件同时成立。
2. **进账是两次读数相减**，不是把口令的 `flowerNum` 加起来。后者会漏掉
   `firstParticipate/give` 那几朵（它**不在**任何口令的结果里）——
   所以输出里的 `进账` 与 `成功 N/M` 是两个独立的数。
3. **有口令被判无效（`200108`）时会自动重听一次**，且**排除已经试过的**（含第一次就成功的）。
   不排除的话第二轮会把同一批再投一遍，而**同一账号**对同一条**正确**口令的第二次请求
   会回 `200112`（已兑换），看起来像"口令坏了"。
   ⚠ 理由**不是**"口令会被消耗"—— 口令**全场通用**（见下面「口令的五条事实」）。
   `--skip-kouling` 时**不重听**（那个开关的语义就是不收）。
   ⚠ `--json` 里 `otherCodes` 是个**集合**（`200112` 与任何没分类的码都在里面），
   要拿**具体是哪个码**看 `draws[].upstreamCode`（口令 + 原始业务码，**保序**；
   `null` = 这一步没解出业务码，与"码是 0"是两件事）。
4. **`--kouling-only` 是只读的**，而默认那条路**会写**：`draw` 是写操作
   （投出去就动了**这个账号**的兑换状态；口令本身全场通用，投过也不影响别人）。
   只想看看今天有没有口令时，一定带上这个开关。
5. **`--codes` 里的分隔符**：换行、半角/全角逗号、顿号都认（口令是从弹幕里抄来的，
   抄的人不会去想该用哪个逗号）；空串与重复项会被丢掉。
6. ⚠ **同一主播同时开两间时只听第一间**（`Rooms[0]`）—— 这是**取舍**不是漏了循环：
   原项目逐间 `await`，那样墙钟时间会变成 N × `--listen-seconds`。
   房间数 > 1 时输出里会**明说**「只听第一间」。
   ⇒ 要两间都听，得改 `run_live_room.go`（把 `Rooms[0]` 换成循环，收集那一步本来就是并发的）。

### 口令的五条事实（2026-09-23 定稿）

> ⚠ 早先文档 / 代码里那句"**口令投出去就收不回来、会消耗**"是**错的** ——
> 它把"**按账号**去重"误当成了"口令被消耗"，已逐处纠正。改这一族之前先读一遍。

1. **只在本次直播有效**：直播时间外不可用，**上一场的口令也不能用**
   （上游原话「口令需当场直播获取才有效哦」= `200108`）。
2. **全场通用**：所有用户共用同一批口令 ⇒ **不存在"消耗口令"这回事**。
3. **每场两个固定口令**（小概率多一条随机的）⇒ 收到 **2~3 条**是正常形状；
   别把"只收到 1 条"当成已收全。
4. **进直播间就会有人发口令**：任意用户（**包括自己和别人**）进入直播间后，系统会
   **以该用户的名义**发一条 ⇒ 弹幕里的口令**署名是谁都能用**，别按"发信人是不是我"过滤。
5. **另一条口令在小红书**：那边没法鉴权、**不做自动化** ⇒ 只能人工找、从 `--codes` 喂进来。
   ⇒ **`--codes` 不是可选项，是另一条的必需入口**。

⭐ `200112` = **同一账号**第二次请求同一条**正确**口令（⇒ 已兑换），与第 2 条**不矛盾**
—— 它**说明口令是对的**（错的回 `200108`），所以不算无效口令。
⭐⭐ **2026-09-23 16:53 首个实拍样本**：同一个账号把两条真口令各投一次之后，**两条都回 `200112`**
（`invalidCodes: null`、`retried: false` ⇒ **没有**触发"重听一次"、也**没有**被记成无效）
—— 口径与 Go 侧行为**双双实证**（原先这里写着"仍**零实拍**"）。
⭐ **"它按账号去重、不是按口令"是用户口述的事实**（2026-09-23 用户明确）：
**两个不同账号投同一条口令，各自都会成功**。
⚠ 本仓**没有这一条的实拍**（唯一一次想补，撞上直播窗口关闭 ⇒ 回的是 `200118`，见下），
但 ⚠⚠ **"本仓没实拍"不等于"这个说法是揣测"** —— 它是**操作这两个账号的人**给出的，
而这类一手口述在本仓是**一等证据**（与"用户拍板"同档）。
⇒ ⚠⚠ **不许把它标成"未定 / 两个方向都不许断言"**：2026-09-23 曾有一版这么标，
那是**把"缺抓包"误判成了"缺依据"**，方向正好反了 —— 见坑表 **#142**。

⭐ `200118` = **"这条口令我认识，但它已经失效了"**（**本场已结束**）——
⭐⭐ **2026-09-23 17:09 实拍**（直播已关、`gateOpen: false`）：**真但已过期**的口令回 `200118`，
而**同账号、同样"已关"**下投**乱码 / 不存在的口令**仍回 **`200108`**
⇒ 它是**口令级**的码、**不是**场次级（服务端**仍然在逐条判口令**）。
⭐⭐ **官方命名**（厂商自己的 H5，`har/liveRoomFeedback.0cdf4040.js`）：
`200118` ⇒ **`popNotLive`**、文案「**需在直播期间内兑换哦**」⇒ 与实验结论逐义相符。
⭐ **输出（2026-09-23 20:3x 起）**：`200118` **单独一类** ⇒ 人读打
「**口令已失效（本场已结束）**」、`--json` 出 `expiredCodes` 字段。
⚠ 早先它与"上游回了个没分类的码"**共用「未分类口令」一个词**，而这一格最常见的成因
恰恰是"**直播已经结束了**" —— 那句话把人往"口令抄错了"那边引（`200108` 才是那个意思）。
判据与做法 → 坑表 **#140**；原始证据 → [`capture/app-live-redflower-samples.txt`](./capture/app-live-redflower-samples.txt) §10.5·§10.6。

**退出码**：「今天没开播」是**正常**结果，退 **0**（与"今天已经签过了"同一档）；
只有"门那三步走不通""六步链解析失败"才退 1 —— 门走不通**不会**被当成"门开着"放行，
否则"凭据坏了"会表现成"门开着、却一条口令也听不到"。

⚠ **未实测的部分**（那天 `chatRoomId: null`，WS 结构性地不存在）：帧的真实顺序、`draw` 的 `200112`。
⭐ 2026-09-23 收口了三处：① `member/apply` 的 `version` 实拍 = `v23.0.2`；
② 帧的真实顺序（见 [`status.md`](./status.md) 的 `command` 取值表）；
③ ⭐ **"WS 签名头取值"这一格被取消了** —— `systemmd5` / `tokenmd5` 只出现在 `member/apply`，
**WS 升级请求一个都不带**；而 `member/apply` 那边服务端**不校验**这两个头
（反证实验：两个头都打成 32 个 0，照样回 `code: 0`「接口调用成功」—— 坑表 **#136**）
⇒ 这一格**没有可核的闸门**，不是"还没测"，是"**没什么可测**"。
⭐⭐ **开播后跑 `node scripts/probe-live-room.js --run`**（`--wire` 看抓包那三条）——
清单的权威版本在**脚本里**，这里不重抄（坑表 #116）。
退出码 **0 核完 / 1 前置成立但有项没拿到（重跑即可）/ 2 没在播**；
⚠ **2 与 1 必须分开**（否则"今天没开播"会被记成"核过了"），且 **0 只代表"这一趟会跑的项"** ——
要 `--code` / 要抓包的几条本来就不在这一趟（坑表 #121）。
⚠⚠ 要抓包的那三条**取证面是 App（`/Applications/mCloud.app`），不是 CLI** ——
本命令的 transport 没设 `Proxy`、WS 也是手写直连 ⇒ 跑 CLI 时代理抓包里**一条记录都没有**
（坑表 #120）。
⭐ 这是**准则**（抓包面必须是**我们没参与的那一端**），不只管这一族 ⇒
见 [`capture-guidelines.md`](./capture-guidelines.md) §1.1。
细节与判据见 [`status.md`](./status.md) 的「直播口令 → 抽小红花」一节与
[`capture/app-live-redflower-samples.txt`](./capture/app-live-redflower-samples.txt)。

## 退出码约定

三档。判据是"**调用方接下来该做什么**"，不是"谁在哪儿把它拦下的"：

| 码 | 含义 | 判据 |
| --- | --- | --- |
| `0` | 跑完了（含"今天已经签过了""今天没开播"这类**正常**结果） | —— |
| `1` | **运行**错误：这次没跑成 | 重试**可能**改变结果 |
| `2` | **用法**错误：调用写错了 | 重试**不会**改变结果，只能改调用 |

⚠ `1` 与 `2` **必须分开**：脚本靠这两个值的差决定"该重试"还是"该改调用"。
⚠ 判据**不是**"解析期能不能判出来"—— 跨层校验（`--records-all` 需要 `--records`；
`--account <越界>` 要看库里有多少账号）发生在 `RunE` 里，性质**仍然是**用法错误 ⇒ `2`。

**已定的两处**（2026-09-22）：

- **按序号点的账号**：**越界**或**为负** ⇒ **`2`**（`signin` 与 `live-room` 一致）。
  换个下标立刻就好、重试不会。⚠ 这两条子命令**一度分了两档**（`live-room` 退 2、`signin` 退 1），
  已对齐到 `2`；判据是上面那条，**不是**"原项目退几"。
- ⚠⚠ **但 `--account 0` 两条命令不一样 —— 别并成一句话**。
  （2026-09-22 **实测订正**：本文件一度写成"两条的 `0` 都退 `2`"，**那是错的**，
  而且它把下面这条**真陷阱**盖住了。）

  | 用例 | 实得 | 含义 |
  | --- | --- | --- |
  | `signin --account 0` | **`2`** | 下标从 1 起 ⇒ 写 `0` 是**调用写错了** |
  | `live-room --account 0` | **不是 `2`**（空库实测 `0`） | **合法**：`0` = "全部启用账号"（它 `--help` 就是这么写的） |
  | 两条的 `--account -1` / `--account 99` | **`2`** | 为负、越界 |

  ⚠ 上表 `live-room --account 0` 那格的 `0` 是**空库**下的值（没有账号可跑，所以直接退 0）。
  有账号时它**会真的跑起来**，退出码取决于那一趟的成败 ⇒ 这一格的判据是
  "**它没被判成用法错误**"，**不是**"它退 `0`"。

  ⚠ **同名 flag 的 `0` 语义可以不同** —— 别按一条命令的口径去推另一条。
  两边**各自的理由都写在各自代码里**（`signin` 侧：Go 的零值分不开"没给 `--account`"与
  "给了 `0`"，所以后者判成用户的错；`live-room` 侧：把 `0` 当作缺省的显式写法，
  `internal/server/runs.go` 的"留空 = 全部启用"也引用它）⇒ 按坑表 **#122** 的纪律
  **没有单方面改**。⚠ **要不要统一（建议 `live-room` 也判 `2`：想要"全部"本来就不给这个开关，
  而 `live-room` 里有不可逆的写操作）留待用户定** —— 见 [`status.md`](./status.md) §六 末尾。
- **按 id 点的账号**（`smid` / `auth` 的 `--account <账号 id>`）不存在 ⇒ **`1`**。
  它的入参是**名字**而不是**位置**（名字合法、只是这个库里没有），与"序号越界"不是同一类；
  且 `smid` 与 `auth` 两条**彼此一致**。
  ⚠ 这两档要不要合成一档，**留到 `auth` 那笔在飞的工作落地后一并看** ——
  现在只动 `smid` 反而会让它与 `auth` 分叉。

⚠ 相关的坑：**#122**（"原项目也这样"要先分「**决定**」与「**只能**」—— 本条一度照抄了
原项目那个**副产品**）、**#127**（把"**哪一层**拦下的"压成一个退出码当判据 ⇒ 层一变，
**红的地方不是真因所在** —— 本条落地时门禁就是这么红的：红的是一条毫不相干的互斥表用例）。

⚠ 上游业务层的 fail 属 info 级，**不影响**退出码；无 error/fatal 时退 `0` 是正确设计。

## CLI 不需要"登录本系统"

数据库就在本机：能跑 CLI 的人本来就能直接 `sqlite3` 读库，
给他加一道"你是谁"**不增加任何安全性**，却让本地运维变别扭。
所以 CLI 一律用 `core.ScopeLocal()`（Rust 侧叫 `Scope::Local`；不过滤，能操作所有人的账号）。

隔离是给**网络上的用户**准备的（WebUI：A 看不到 B 的账号）—— 那里用户拿不到库文件，
边界才有意义。过滤逻辑只有一份：查询写 `(?n IS NULL OR owner = ?n)`，
两种范围共用同一句，所以"某条查询漏了归属条件"在结构上不可能发生。

**WebUI 那侧确实要**：`POST /api/session` 登录、每个请求带 cookie 解析出 `UserId`，
再据此取 `core.ScopeUser(&谁)`（Rust 侧写法 `Scope::User(谁)`）。
两条硬规则（见 [`rust-rewrite-plan.md`](../../mcloud-rust/docs/rust-rewrite-plan.md) §3.7）：

- **没初始化就只暴露初始化**：库里没有用户时，除 `/api/setup` 与健康检查外一律 `503`；
- **其余接口一律要会话**，且**白名单**判定豁免（新加的路由默认是"需要登录"）。

CLI 新建的云盘账号会归**库里首个用户**（没有用户则保持无主，等 `user init` 时认领）——
这不是权限检查，而是"账号必须有主人"：否则网页端按隔离规则看不到它，
会出现"扫码成功了、网页里却没有这个账号"。

## 旧数据迁移

```bash
go run ./cmd/mcloud migrate --repo-root <旧项目路径> --dry-run
```

（同上面那条订正：**不要**写成 `go run ./cmd/mcloud -- migrate …`。）

`--dry-run` 是"在内存库上跑**完全相同**的路径再丢掉库"，不是另写一套只检查不写入的代码
（两者会各自演化，预演就会失去意义）。

硬底线：

- **解析不到的账号引用绝不回落到"全部账号"** —— 那会把"过去没跑"变成"对所有人跑"。
  定时任务导入为**停用**，组合（无 `enabled` 字段）**整条跳过**；
- 掩码 `AccountId` 撞车必须在**任何写入之前**中止（连台账都不落）；
- 源目录**只读**；"归档"是为了让新项目自带可离线重放的原始数据，**不是回滚用的 `.bak`**。

迁移还会**回填凭据**（`asign.json` 的 `auth` → `account_state.authorization`，见上面第 7 条）。
报告里的 `凭据回填 N` 是**本次实际补上**的个数 —— 没有缺口可补的不计入，
所以第二次运行会看到 `0`，那个数字才有意义。

cd web && npm install && npm run build      # 前端产物到 web/dist
go run ./cmd/mcloud-server                   # API + 前端，默认 http://127.0.0.1:8787
