# mcloud 用户使用指南

`mcloud` 是一个跑在**你自己**的电脑或服务器上的小工具，用来自动完成
**中国移动云盘**的日常操作（签到、领 AI豆、兑换奖品、直播口令换小红花……），
跑完还能把结果推给你。

整个工具**只有一个程序文件**，不用装别的依赖。跑起来之后有**两种用法**，
**先挑一个**，不用都读：

* **想要网页界面**（浏览器里点点鼠标就行），而且一台机器还想**多人共用**、各人看各人的
  ⇒ 看 **第一部分：WebUI 篇**。
* **只有一台没有网页的机器**（开不了浏览器、也没连公网），或者你**就想敲命令**
  ⇒ 看 **第二部分：CLI 篇**。

> 两篇各看各的即可。后面的「常见问题」和「进阶」两边都用得上。

---

## 0. 先拿到程序

产物按平台命名：unix 是 `mcloud-v<版本>-<target>.tar.gz`，Windows 是 `...zip`
（**不再有 `.tar.xz`** —— 一个平台只出一种包）。
`<版本>` 取自 `Cargo.toml` 的 `[workspace.package] version`（发 tag 时以 tag 名去掉 `v` 为准），
**别背数**，现算：

```bash
sed -n '/\[workspace.package\]/,/^\[/p' Cargo.toml | sed -n 's/^version = "\(.*\)"/\1/p' | head -1
```

### 解压与校验

```bash
# Linux / macOS：unix 一律 tar.gz
tar -xzf mcloud-v<版本>-x86_64-unknown-linux-gnu.tar.gz
cd mcloud-v<版本>-x86_64-unknown-linux-gnu

# 校验（包内附 .sha256）
shasum -a 256 -c ../mcloud-v<版本>-x86_64-unknown-linux-gnu.sha256
```

```powershell
# Windows
Expand-Archive mcloud-v<版本>-x86_64-pc-windows-msvc.zip -DestinationPath .
cd .\mcloud-v<版本>-x86_64-pc-windows-msvc
Get-FileHash ..\mcloud-v<版本>-x86_64-pc-windows-msvc.zip -Algorithm SHA256
```

解压出来的就是**一个可执行文件 `mcloud`** —— 它既是网页界面，也是命令行。

> **不带参数 = 起网页服务、带子命令 = 命令行**。

### ⚠ Linux 有三份，别拿错

拿错的症状是：
`./mcloud: /lib/x86_64-linux-gnu/libc.so.6: version GLIBC_2.39 not found` ✗

* **x86_64**（`x86_64-unknown-linux-gnu`）：动态链接 —— 构建于 Ubuntu 24.04
  （glibc 2.39）+ **系统** OpenSSL ⇒ 要在 **glibc ≥ 2.39** 且装了 `libssl3` 的发行版上跑
  （Ubuntu 24.04+、Debian 13+、Fedora 40+ 一类）。体积最小 ✓。
* **x86_64 静态**（`x86_64-unknown-linux-musl`，2026-10-06 起 ✓）：glibc 与 OpenSSL
  **都静态链进二进制** ⇒ **任何** Linux x86_64 都能跑（CentOS 7、Debian 11 这类老发行版
  也一样 ✓），运行时**什么都不用装** ✓；代价是体积大 2–3 MB ✓。**拿不准就下这份** ✓。
* **arm64**（`aarch64-unknown-linux-gnu`）：走 `cross` 交叉编 —— 镜像基线更老
  （glibc 2.23 那一档），且 OpenSSL 是 `vendored`（从源码编、**静态链**）⇒
  **不用装 `libssl`**，代价是体积大 2–3 MB。

判断手上那份是哪种，一条命令：

```bash
ldd ./mcloud        # 静态那份会说 "not a dynamic executable"（退出码非 0 是正常的 ✓）
```

⚠ 在这条之前，更老的发行版只能"自行从源码构建"（本文件原先就是这么写的 ✗）——
现在下**静态**那份即可 ✓。

# 第一部分：WebUI 篇

> 面向**完全不懂编程**的人。照着往下做就行。

## 1. 起起来

进到解压出来的那个目录，敲文件名（或者直接双击它）：

```bash
./mcloud                   # Linux / macOS
.\mcloud.exe               # Windows
```

⚠ **后面什么都不要加** —— 不加参数就是起网页服务。
（`mcloud serve` 和它**完全等价**，是同一个命令，写哪条都行 ✓。）

敲完屏幕上会出现两行字，**第一行里那个网址就是你要的地址**：

```
INFO mcloud: mcloud 启动 data_dir="data" tasks=<已注册任务条数>
INFO mcloud: 监听 http://127.0.0.1:3000
```

把 **`http://127.0.0.1:3000`** 复制到浏览器地址栏，回车。

⚠ 这个窗口**要一直开着** —— 它就是服务本身，窗口关掉服务就停了
（想让它自己常驻、开机自启，见「进阶 → 常驻与自启」）。

## 2. 第一次打开：建管理员、登录

第一次打开会看到「**首次使用，请创建管理员账号**」：

1. 填一个**用户名**（随便起，比如 `admin`）；
2. 填一个**口令**（默认至少 8 位）；
3. 点创建。

> 这个账号**只用来进这个管理界面**，跟你的移动云盘账号是两回事 ——
> 云盘账号要到「账号」页里加。

建好之后页面变成登录页（「请登录以继续」），用刚设的用户名和口令登进来即可。
之后再打开浏览器就是直接登录。

## 3. 左边那一列，每页是干嘛的

登录后左侧从上到下就是这十页（手机上是屏幕最下面那一排），**顺序与界面一致**：

**总览**
一眼看清现状：账号还在不在、今天 AI豆进账多少、最近跑过什么、接下来要跑什么。
每天打开第一眼看它就行。卡片上的数字点一下就是对应的详情。

**账号**
这里加你的移动云盘账号（扫码 / 短信 / 账号密码），也在这里看已经加过哪些账号。
第一次用**先来这里加一个号**，别的地方才有东西可跑。
页面里还挂着两个子入口：**账号配置**（改这个号的参数）和**上游状态**（看它在移动云盘那边是什么样）。

**任务**
所有能跑的任务都在这（签到、领取、翻倍……）。
挑一个任务、勾上账号、点运行，右边就能实时看到执行日志。
想改某个任务的参数，点任务卡片上的配置进去。

**兑换**
用 AI豆兑换奖品（网易云音乐月卡这类）。
⚠ 这里点下去是**真扣豆**的，所以点"兑换"之后会再弹一次确认框 —— 看清名字和价格再点。

**直播**
收直播弹幕与小红书里的口令，再把口令换成小红花。
要跑这个就先在这一页把口令、听多久这些填好，再点运行。

**定时**
让任务**按点自动跑**：几点跑、跑哪个、给哪些账号跑，都在这配。
配一次就不用管了，到点它自己跑，结果去「历史」里看。

**编排**
把好几个任务串成一条链，按顺序一个一个跑（比如先签到、再领豆、最后兑换）。
适合"每天固定一套动作"的场景；配一次，之后让「定时」去触发它。

**历史**
两个标签页：一个是**历次执行的结果与耗时**，另一个是整个服务的**运行日志**。
想知道"昨晚那一趟到底跑成没有、为什么没跑成"，就来这里翻。

**推送**
配"什么情况下通知我、通知发到哪里"（PushPlus / 企业微信 / 邮件……）。
左边列规则，右边改这条规则的详细设置。不配也不影响跑，只是不会有通知。

**设置**
分四节：**服务 / 安全 / 事件推送 / 关于**。
*「服务」*里有版本信息、**存储信息**（数据在哪、日志占多大、能改保留上限）和服务操作 ——
服务操作里那枚「**导出配置**」点一下就把你的配置下载成一个文件（账号、规则、定时这些全在里面）；
想把配置倒回来（导入）要到命令行里做，界面上**故意没放**（那是换机器、搬配置用的，见 CLI 篇的「换台机器」一节）；
*「安全」*里可以**改你自己的口令**、调口令长度下限与会话时长；
*「事件推送」*是"面板自己出状况时推不推"（登录、性能那几类）；
*「关于」*是版本与说明。

## 4. 多人共用一台机器

一台机器跑一个 `mcloud`，可以让**好几个人各自登录**：各人看到的是**各自的账号和记录**，
互不打扰；而定时、兑换这些自动跑的事**共用同一份**，不用每人装一份。

**加人**要在那台机器上敲一条命令（就是下面 CLI 篇里的那几条）：

```bash
mcloud user list                     # 先看现在有谁、谁是管理员
mcloud user add 张三 一个够长的口令    # 加一个普通用户
mcloud user passwd 张三 新口令         # 改他的口令
```

* 空实例上**第一条** `add` 建出来的就是**管理员**（不用再走网页上的初始化向导 ✓）；
* ⚠ 这三条跑完**要重启一下服务**才认（关掉那个窗口、再 `./mcloud` 起一次）。

## 5. 凭据会自动续，不用管

登录云盘账号之后拿到的那串凭据会过期。**系统每天到点会自动检查一次**
（默认每天凌晨 **03:00**），快到期的账号会**换一串新的凭据**，换完照常用 ——
**你什么都不用做**。

想改时间、或者临时想手动换一次：**账号 → 账号配置** 里那张「**凭据自动刷新**」卡就是。
⚠ 每张卡只管**你自己名下**的账号（各人管各人的 ✓）。

# 第二部分：CLI 篇

> 给"只有一台没有网页的机器"、或者**就想敲命令**的人。**这一篇很短，是故意的**。

## 1. 它给谁用

**CLI 就是给"这台机器上的那一个人"用的** —— 也就是管理员。

所以它**没有任何"选谁"的参数**（没有 `--user`、没有 `--owner`）：
敲下去，作用的就是你自己那一份，不用挑也不用填。
多用户那套是网页界面的活。

> 命令分**两组**（`mcloud --help` 打出来的就是这两组）：
> **「服务端 / WebUI 命令」**（`serve`、`user …` —— 给"多人共用一个实例"用的）
> 和**「个人 CLI」**（其余全部 —— 只作用于本机那一个用户）。
> 下面列的是个人 CLI 里常用的那几条。

## 2. 常用就这几条

```bash
mcloud                    # 起服务（= 起网页那个服务，不带参数就是它）
mcloud run                # 立刻把「系统默认每日任务」跑一遍（跑在你自己名下所有账号上）
mcloud login qr           # 登录云盘账号（扫码；也可 sms / app / password / device）
mcloud tasks              # 看看有哪些任务可用
mcloud user list          # 看看这台机器上有哪些登录账号、谁是管理员
mcloud help               # 所有命令的清单（`mcloud --help`、`-h` 同）
```

`mcloud run` 第一次跑会告诉你**还没有可跑的账号** —— 先 `mcloud login qr` 登一个再来。

⚠ `mcloud run`（不带参数）是**立即**把「系统默认每日任务」跑在**本机管理员名下的全部账号**上 ✓
（**不是**库里全部账号 ✗：多用户实例里别人的账号一个都不碰 ✓）。
`mcloud run --help` 打的是帮助清单、退出码 0 ✓（`run help` / `run -h` 同）。

其余命令（`cron`、`pipeline run`、`auth`、`push`、`live-room` …）都在
`mcloud help` 打出来的清单里，需要时再看 —— 这份指南**故意不把它们全抄一遍**
（那是参考手册的活）。

> 敲了一个不认识的命令时，它会把同一份清单打到屏幕上并以退出码 2 结束 —— 不是出错，是在提醒你怎么用。

## 3. 换台机器：把配置搬过去

这一节的两条命令，是把你这台机器上的配置**打包成一个文件**，再倒到**另一台机器**上。
三种时候用得上：

* **换机器** —— 旧电脑不用了，把配置搬到新电脑，省得一样样重新配、重新登录；
* **留个备份** —— 存一份文件，机器坏了照它恢复；
* **给没有网页的机器配东西** —— 那台机器开不了浏览器，先在别的机器上配好，再把文件搬过去。

一条导出、一条导入，就这两条：

```bash
mcloud config export --out 我的配置.json   # 导出：把本机这个用户的配置写成一个文件
mcloud config import 我的配置.json         # 导入：把那个文件倒进本机这个用户
```

`export` 后面不写 `--out`，内容就直接打在屏幕上（想存成文件，自己把它重定向进去）。
忘了怎么写，敲 `mcloud config`，它会把用法打在屏幕上：

```
用法：
  mcloud config export [--out <路径>]       导出本机用户的配置
                                            （省略 --out 就打 stdout，可重定向到文件）
  mcloud config import <路径> [--with-instance]
                                            把那份 JSON **按 id 合并**到本机用户
                                            （同 id 覆盖、本机多出来的保留）
  mcloud config help                        打印帮助（`--help` / `-h` 同；
                                            打的是 `mcloud --help` 那份命令清单）
  mcloud config                             不带子命令 = 打印下面这份详细用法
```

**这个文件等于你的登录态** —— 里面有账号凭据、设备指纹、推送渠道的 token，
拿到它的人就能替你用这些账号。所以：**别随手发给别人、别提交进版本库、搬完就把文件删掉。**

导入是**按 id 合并**：文件里有的、本机也有同一个的（同一个账号、同一条规则），
就盖掉本机那条；本机没有的就加进来；**本机多出来的原样留着，不会删**。
导入前它会把要改的文件自动备份一份（文件名带时间戳），中途出错会自动回滚。
导入只是改了盘上的文件，**要重启一下服务才生效**（关掉那个窗口、再 `./mcloud` 起一次）。
搬完**不用重新登录** —— 账号和凭据跟着文件一起过去了，直接就能跑。

> 两条命令都只作用于**本机这个用户**（就是第 1 节说的那个管理员），
> 没有 `--user` / `--owner` 可填。要搬别人的配置，让他自己在网页界面里配。

## 4. CLI 不做什么

两件事**故意不做**，请到网页界面去配：

* **不配推送规则**（什么情况推、推到哪里）；
* **不配自动定时**（什么时候自动跑）。

这两样都是"列一堆条目、一条条改"的活，敲命令太别扭 —— CLI 保持简单。

# 第三部分：常见问题

**页面打不开，或显示「页面加载失败，请检查网络后重试」（左下角写着「后端连接中断」）**
说明服务没在跑，或者刚重启还没起来。回到那个窗口看看是不是被关了，重新起一次：

```bash
./mcloud
```

等它打出「监听 http://127.0.0.1:3000」再刷新页面就行。

**起服务时提示「监听 127.0.0.1:3000 失败 / Address already in use」**
这个门牌号（端口）已经被别的程序占了 —— 多半是**你自己已经起过一个 mcloud**。
先把那个关掉；或者换一个门牌号起：

```bash
MCLOUD_ADDR=127.0.0.1:3001 ./mcloud
```

⚠ 换了门牌号，浏览器也要跟着开 `http://127.0.0.1:3001`。

**我的数据在哪？怎么备份？**
就在你**运行它的那个目录**下的 `data/` 文件夹里（账号、记录、定时、日志全在里面）。
**把整个 `data/` 目录拷走，就是一份完整备份**；换机器时把它放回新机器的运行目录即可。
反过来也成立：**在哪个目录跑，数据就在哪里** —— 换个目录跑等于从零开始一套新的。

**换台机器，怎么把配置搬过去？**
在**老机器**上把配置导成一个文件，把文件拷到**新机器**，在新机器上导入，再重启一下服务：

```bash
mcloud config export --out 我的配置.json   # 老机器上跑，生成一个文件
mcloud config import 我的配置.json         # 新机器上跑（文件已经拷过去了）
```

搬完**不用重新登录** —— 账号和凭据都跟着文件过去了，直接就能跑。
这个文件等于你的登录态，别乱发、别提交进版本库、用完删掉；详见 CLI 篇的「换台机器」一节。

**忘了管理员口令**
在那台机器上敲两条（`list` 里能看到用户名）：

```bash
mcloud user list
mcloud user passwd <用户名> <新口令>
```

然后重启一下服务。⚠ 已经登录着的浏览器**不会**因此被踢下来。

**`127.0.0.1:3000` 是什么？别人能打开吗？**
`127.0.0.1` 就是"这台机器自己"的意思，所以这个地址**只有本机能打开**，别人的电脑打不开。
想让别人也能用，得自己把它挂出去（反向代理 / 内网访问），这里不展开。

**Windows 上 Defender / SmartScreen 报警、macOS 上双击打不开**
见「进阶 → 平台注意事项」。

# 第四部分：进阶

## 平台注意事项（这三条都是踩过的）

**Linux** —— **x86_64** 那份用系统 TLS（`native-tls` → OpenSSL），需要目标机有 `libssl`
（**arm64** 那份是静态链的 vendored OpenSSL，不装也能跑）：

```bash
sudo apt install -y libssl3        # Debian/Ubuntu
sudo dnf install -y openssl-libs   # Fedora/RHEL
```

**macOS** —— 产物**未压缩**（UPX 会破坏 arm64 Mach-O 的代码签名，M 芯片上直接跑不起来），
但二进制没有签名，从浏览器下载会被 Gatekeeper 拦：

```bash
xattr -dr com.apple.quarantine ./mcloud
```

（或右键 → 打开 → 「仍要打开」。终端里 `tar` 解出来的通常不带 quarantine。）

**Windows** —— 产物**用 UPX 压过**（体积约为原来的 1/3），代价是
Defender / SmartScreen **可能误报**：弹窗里走「更多信息 → 仍要运行」，或把文件加白名单。
介意这一点就自行从源码构建（`npm run build` 后 `cargo build --release`）。

## 三个环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `MCLOUD_ADDR` | `127.0.0.1:3000` | 监听地址（门牌号） |
| `MCLOUD_DATA_DIR` | `data`（相对当前目录） | 数据目录 |
| `MCLOUD_ALLOW_LOCAL_PUSH` | 关（缺省） | ⚠ **危险开关**：放行"推送地址指向本机/内网"。只认真值 `1` / `true` / `yes` |

```bash
MCLOUD_ADDR=0.0.0.0:3000 MCLOUD_DATA_DIR=/srv/mcloud ./mcloud
```

⚠ 用的是 `MCLOUD_DATA_DIR`，**不是** `MCLOUD_DATA`；`PORT` 环境变量会被忽略。

### 推送地址的闸与 `MCLOUD_ALLOW_LOCAL_PUSH`

推送（自定义 POST / 企业微信机器人 / TG …）的地址是**用户自己填的整条 URL**，
而发请求的是**服务进程** ⇒ 不设闸的话，任何能改推送配置的账号都能让服务去打
`127.0.0.1:3000/api/...`、云元数据 `169.254.169.254`、内网段 —— 一条**盲 SSRF**
（响应体不回给调用方，但状态码会进推送日志 ✓）。本仓是**多用户**、`MCLOUD_ADDR`
还可以绑到 LAN ⇒ 那是真的权限边界，不是"管理员自伤"。

所以推送地址**默认**只允许公网，两道判据：

1. **字面量**（不联网）：scheme 只许 `http`/`https`；`127.0.0.1` / `10.x` / `192.168.x` /
   `169.254.x` / `0.0.0.0` / `100.64.x`(CGNAT) / `[::1]` / `[fd00::]` / `[fe80::]` 这类
   一律拒；`localhost` / `*.local` / `*.internal` 这类**名字**也拒；
2. **真解析出来的 IP**（要 DNS，带超时）：域名解析出来的**每一个** IP 都必须是公网，
   只要有一个不合格就拒。⚠ **解析失败 / 超时也拒**（不是"解析不出来就放过"）。

⇒ `http://127.0.0.1.nip.io:3998/` 这种"**名字里嵌着回环 IP**"的写法**会被拒** ✓。

**什么时候才需要那个开关**：你**自愿**把推送打到本机/内网的地址上（例如自建的
`http://192.168.1.10:8080/hook`，或者家里 NAS 上的 webhook）。这时才设：

```bash
MCLOUD_ALLOW_LOCAL_PUSH=1 ./mcloud
```

三条要知道的：

* ⚠ 它是**服务级 / 管理员级**的（进程环境变量），**不是**页面上每个用户能自己勾的
  开关 —— 后者等于把闸拆了（普通用户勾一下就能拿服务当内网探针 ✗）；
* ⚠ 放行时**一定**会在日志里留一条 `warn`（带那条 URL ✓），**不会静默放行**；
* ⚠ 它只放宽"**地址指向哪**"；`file:` / `gopher:` 这类 scheme 与格式错的 URL
  照旧拒（开关管不着）✓。

⚠ 已知残留：这道闸**挡不住** DNS rebinding / TOCTOU（解析完到真正连上之间 DNS 还能变 ✗）。
要做到那一步得把连接**钉在已核过的 IP** 上，本仓现在做不到，理由写在
`crates/mcloud-app/src/push.rs` 的 `validate_push_url_resolved` 上 ✓（别把它当成已解决 ✗）。

## 定时与编排从哪来

**创建**不在命令行 —— 在 WebUI 里配。命令行只负责**跑**：

```bash
mcloud cron <定时id>          # 给系统 crontab 调用（跑一条已配好的定时）
mcloud pipeline run <编排id>  # 跑一条已配好的编排                             # （= 立即把「系统默认每日任务」跑在**本机管理员名下的全部账号**上，
                             #   不用先知道 id；**不是**库里全部账号 ✗）
```

顶层命令清单以 `crates/mcloud-server/src/cli/run.rs` 的分派为准，**别背数**，现算：

```bash
grep -n '^        Some("' crates/mcloud-server/src/cli/run.rs
```

## 常驻与自启

**Linux（systemd）**

```ini
# /etc/systemd/system/mcloud.service
[Unit]
Description=mcloud
After=network.target

[Service]
User=mcloud
WorkingDirectory=/srv/mcloud
ExecStart=/srv/mcloud/mcloud
Environment=MCLOUD_ADDR=127.0.0.1:3000
Restart=always

[Install]
WantedBy=multi-user.target
```

**macOS（launchd）**：写一个 `~/Library/LaunchAgents/<label>.plist`，
`ProgramArguments` 指向 `mcloud` 的**绝对路径**，`KeepAlive` 设 `true`，
`WorkingDirectory` 指向放 `data/` 的目录。

⚠ 别把 `WorkingDirectory` 与 `MCLOUD_DATA_DIR` 搞成两处不一致 —— 那会出现
「服务明明在跑，账号却是空的」这类看起来像 bug 的现象。

## 升级与卸载

* **升级**：停掉服务 → 用新包里的二进制覆盖旧的 → 再起。`data/` 不用动（放数据目录里就不会丢）；
* **卸载**：删二进制 + 删 `data/` 目录即可（它不往系统别处写东西）。

## 数据放在哪、能占多大

| 落点 | 里面是什么 | 谁管它的上限 |
|---|---|---|
| `data/*.json` | 账号、定时、编排、设置、会话…… | 都是 KB 量级，不设上限 |
| `data/history.json` | 运行记录（跑了什么、结果如何、耗时、明细） | 历史保留条数（默认 200） |
| `data/logs/<run_id>.json` | **运行日志正文**（一次运行一个文件） | 单次运行行数（默认 2000）＋ 目录总量（默认 64 MB） |

> ⚠ 2026-10-09 起**日志只在磁盘上**：启动时**一个日志文件都不读**进内存，
> 打开某次运行的日志时才按需读盘（内存里只留最近碰过的几个 run）；
> 界面上的「运行日志」是**分页**取的（先给最近 500 行，再往上翻）。
> 升级前内联在 `history.json` 里的那份旧日志会在启动时自动搬进 `data/logs/` ✓。

三个上限都在 WebUI 里改：**设置 → 服务 → 存储信息**（那一卡也显示日志目录的
当前占用 / 上限）。改完**立刻生效**：超出部分按**最旧的**淘汰（运行记录本身不动
—— 你照样看得到"跑过什么、结果如何"，只是更早那些的回看日志没了）。

## Docker（Linux 容器）

不想装运行时依赖、想用容器跑，就这一条路：

```bash
git clone https://github.com/asunajs/mcloud.git && cd mcloud
docker compose up -d --build     # 构建镜像（十几分钟）+ 起服务
open http://127.0.0.1:3000       # 首次进「创建管理员」向导
```

镜像里是**静态 musl 二进制**（不依赖 glibc / libssl）+ `ca-certificates` + `tzdata`，
非 root 用户（uid **1000**）跑，数据全在命名卷里（容器内 `MCLOUD_DATA_DIR=/data`）。

三条与二进制部署**不一样**的地方：

* `MCLOUD_ADDR` 在镜像里默认是 **`0.0.0.0:3000`**（容器里绑 `127.0.0.1` 的话端口映射打不进来）；
  暴露面由 compose 的 `ports` 决定 —— 默认只发到宿主机的 `127.0.0.1:3000`；
* 用**绑定挂载**（`./data:/data`）时，宿主机目录要先 `sudo chown -R 1000:1000 ./data`；
* 在容器里用 CLI 改用户/口令之后**要重启容器**（`mcloud user add|passwd` 写的是
  `data/users.json`，而服务启动时把这类文件**整份读进内存** ⇒ 不重启的话用它登录会 401，
  而且服务下一次写这个文件会拿陈旧快照把刚加的人覆盖掉）。

完整的说明（备份/升级、HTTPS 与反代、限速在反代后为何退化、常见故障、以及**哪些还没验过**）
见 [`docs/docker.md`](docker.md)。

## 如果你是来改前端的

下载用户看到这里就够了。改前端要注意一处**默认值不一致**：
`web/vite.config.ts` 的 dev 代理写死目标是 **38123**，而服务默认监听 **3000**
⇒ 照着上面启动服务、再 `cd web && npm run dev`，页面能开但所有接口都会连不上（静默）。
两者对齐即可：

```bash
MCLOUD_ADDR=127.0.0.1:38123 ./mcloud   # 让后端去迁就 dev 代理
```
