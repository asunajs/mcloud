## 0. 一句话结论

`batchTrash` 打在**非空目录**上：上游认，且**内容跟着一起没了、没有退回到根目录** ⇒ R7 那一格闭合。
顺带两口第一次真跑成立：**建目录**（`file/create` + `type:"folder"`）与**把文件传进子目录**
（`file/create` 带非根 `parentFileId`）——后者今天**零生产调用点**，此前只是"旧 TS 这么发过"。

## 3. 逐格判读（对上 `docs/pending-decisions.md` **R7**）

R7 登记时给的是两档可能 + 一句"怎么测"。四趟里读到的是**第三档**：

  - **不是"删不掉"**：③ 那一枪四趟全被上游认，且 B/C/D 里根目录那一页当场不再列它；
  - **也不是"删掉目录、内容退回根"**：那枚 `asign-trashkid-*` 在四趟里**都没出现**在根目录
    那一页 ⇒ 清理链若将来接目录，不需要"把子文件也记进名单"这一半；
  - 读到的是：**目录连同内容一起进回收站**（列那个被删的目录 ⇒ 读得出来、**0 项**）。
    这一句现在**有回收站侧读数**了（同日第廿七趟第一次真打 `POST /hcy/recyclebin/list`，
    见 [`app-cloud-recyclebin-samples.txt`](app-cloud-recyclebin-samples.txt) §5）：删一枚非空目录 ⇒
    回收站里**只多一条**（那条目录），里面那枚文件**不单列** ⇒ 上一句从推断升成实测。
    ⚠ 同趟另读到一条口径：那一口**有秒级不回**（当场那遍读不到、等 20s 后读到）⇒
    「当场回读说没有」不能当「它没进回收站」的判据。

A 趟那一次"删后根目录仍列着目录（32 项）"怎么落：它与 B/C/D 差在**回读时机**，
因为同一号同一链跑三趟有两趟当场就不列了。⚠ 这只说明"**必须补第二枪**"那一档**不成立**
（B/C/D 各只打了一枪），**不构成**"A 那一次一定只是滞后"的 proof ——
要判它得在删后连读多遍并带时间戳（今天的 `④′` 已经是这一半的做法，A 趟没跑上）。
⚠ 同日第廿七趟在**回收站那一口**上实测到"秒级不回"（`app-cloud-recyclebin-samples.txt` §5），
⇒ 它给 A 趟那一格提供了一个**同族解释**，但那一格读的是**网盘侧** `file/list`、不是同一口
⇒ 这一句只能当**假设**，不构成"A 那一次就是滞后"的判定。

## 4. 顺带读到的三格（都是"接口层今天算不算通"）

    `uploadId` 与 `uploadUrl` 都为缺 ⇒ 与 folder 型那两条实拍同型（实拍里 `data.uploadId`

## 6. 探针侧修的一处越界（不是上游的账，是我们自己的）

头三趟（A / B / D）的**传输层账本**把 `PUT` 那一枪的**对象存储主机 + 对象键**
逐字打进了 stdout（当时那一份查询串只有长度，所以没漏签名，但写入入口的主机与键漏了）。
`target/` 不入库 ⇒ 没进成文，但那正是"预签名 `uploadUrl` 绝不进日志"这条纪律的破口。

修法：记录器对 `MethodPut` 那一枪**整条 URL 换成占位**（`PUT <预签名写入入口：主机与路径不打印>`），
只保留"发了几发"那一格读数；并加反向测试
`TestLiveProbeRecorderKeepsPresignedURLOutOfOutput`（把占位换回真实 `host+path` 它就红）。
**只有 C 那一趟是修法后跑的**（§7 抄的就是它）；A / B / D 那三份修法前的 stdout 已删掉，
本仓今天不留任何一份带着那一格的日志。细节进坑表（本轮编号见 `docs/migration-pitfalls.md` 抬头）。

### ⭐ 这一格闭合：实拍那句在本仓真打上成立

  - **上游不把撞名当失败**：第二发的信封三格与第一发**逐字相同**（`code:"0000"` /
    `success:true` / `msg` 缺键）⇒ [upstream.ParseCloudFileCreate] 走的是**成功**那一条，
    `exist=true` 读得到 ⇒ 编排层那一支 `created.Exist`（[CloudUploadExists] 那一档）
    **不是死分支**。此前这一句只是"照旧 TS 抄来"，今天它有本仓的现场值。
  - **交回的是已有那枚**：两发 fileId 在内存里**相等**（长度都是 33；真实值不进成文），
    而网盘侧整名仍 **1 枚**、那一页只涨 1 条（31 → 32）⇒ `fileRenameMode:"refuse"` 确实
    "不另起一个"，[upstream.CloudRenameModeRefuse] 头注那句**由实拍升成实测**（同一条注释里
    "别搬去传文件"那半句仍无读数，见下面边界）。
  - 三趟同一档、且都是**第一次**在这口上读到 `exist:true` ⇒ 前面五趟（第廿六／廿八／廿九／卅／
    卅一趟）那句"每一发都 `exist:false`"不是上游的口径，只是随机名撞不上。

### 方法格：零样本那一档要**主动造**，但造之前要先钉"撞的是谁"

这一族五趟都靠随机 hex **躲开** `exist:true`（躲开的是"删掉用户原有目录"这一后果），代价就是
那一档一直零样本。第卅二趟的做法是**把撞名变成设计**，同时用 ⓪ 那一遍网盘侧对照把
"这一枚属不属于本趟"钉在前面：⓪ 命中 > 0 ⇒ 判据不成立、当场收手且**不删**（那是上一趟的残留，
归 R37ⓒ 那批处置），⑤ 的收场名单因此可以按 id 直接列（都是本趟造的）。
⇒ "要读一条危险分支的现场值"与"不动用户内容"这两件不冲突，缺的只是**先读一遍对照**。

### 这一趟没答的（四条，都不许顺手放宽）

  - **同名的是文件而不是目录**：`refuse` 只在 `type:"folder"` 上真打过；
    [upstream.CloudRenameModeRefuse] 头注那句"同名**文件**用 refuse 会怎样零样本"**仍然零样本**
    （文件的真实链走 `auto_rename`，本仓没有发 refuse 的文件型）。
  - **在非根目录里撞名**：两发都发在 `/`。`parentFileId` 换成一枚子目录时同样问句**未测**
    （第廿六趟证明过"非根 parentFileId 上游认"，但那一趟没测同名）。
  - **对方那一枚是用户本来就有的**：⓪ 命中 > 0 那一档探针只念"收手不删"⇒ 上游在那一档回什么
    **没有读数**（这一档**补不了**：要它就得拿用户真实目录名去发写请求，越界）。
  - **已进回收站的那枚同名目录**：会不会让 `file/create` 回 `exist:true`（"回收站里占不占名"）
    **未测** ⇒ 执行口现成：拿 §9／§14 那几枚残留的**整名**再发一发建目录（都是我们自己造的名）。
    ⚠ 那是**下一趟**的一问，本趟不混着答（一趟只答一问）。

### 账本与残留

每趟 **5 枪 / 3 类**（`file/create` ×2 + `file/list` ×2 + `batchTrash` ×1；三趟逐字相同）：

```
一共 5 枪 / 3 类
  POST personal-kd-njs.yun.139.com/hcy/file/create ×2
  POST personal-kd-njs.yun.139.com/hcy/file/list ×2
  POST personal-kd-njs.yun.139.com/hcy/recyclebin/batchTrash ×1
```

网盘侧**不留东西**（每趟"两发之后 32 项"、下一趟"建前"又回到 31 项 ⇒ 收场那一发真的生效了）。
回收站侧净增 **3 枚**：同日只读复跑（`TestLiveProbeSameFileRetrashReread`，一枪写的不发）
念到第一页 `40 条 / 我方前缀 40 条` —— 与第卅一趟那次的 **37** 相差正好是本趟这三枚；
八枚 `retrash*` 整名仍各出现 **1 次**（`trashedAt` 全是各自那趟的时刻 ⇒ §13 那句"跨趟也不重复入账"
又多一遍读数）。⚠ 那一支按 `retrash` 系四个中段数条，`refusedir-` 不在其内 ⇒
本趟那三枚只落在 `40` 这个总数里，没被逐枚念出来。**并入 R37ⓒ 的合计因此是 20 枚**（原 17 枚）。

### 待办（这一格补得了的）

  2. 「回收站里那枚同名目录占不占名」那一问（上面边界第四条）——它要新开一趟，形状与本趟同档；
  3. `file/list` 那一口**翻页**（今天固定一页）：命中数在有下一页游标时只是下界，R36 的全树走查
