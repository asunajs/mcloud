## 0. 一句话结论

这一口**打不通的假设被推翻了**：按 App JS 里那份逐字形状（体只有 `pageInfo:{pageCursor,pageSize}`、
`pageSize` 写死 100）、沿用 `batchTrash` 那一档头画像，上游**直接认**，回的是**真回收站列表**。
于是 R7 剩下的那一格从推断变成读数：

⭐ **删一枚非空目录 ⇒ 回收站里只多**一条**（那条目录），里面那枚文件不单列**；
而且**这一口有秒级延迟** —— 同一趟内"删 → 当场读 → 等 20s → 再读"，本趟那枚目录
**整名**命中 `false → true`、条数 `33 → 34`。

后一句是本趟最要紧的一处**口径**：**「当场回读说没有」不能当「它没进回收站」的判据**（§5）。

同日更晚的第廿八趟把 §10 里"多层嵌套"那一格换成了读数（**§11**）：**两层子树**（1 枚子目录 +
2 枚文件）删最外层，回收站里**仍然只留一条**；而 `trashedDirStatistics` 那一格**同形状三趟读到两档**
（`1/0/0` 两趟 / `1/1/64` 一趟）⇒ 它**不是**由形状唯一决定的数（本文第一版把这一格写成"读到了真正
数的是哪一档"，那是过强的一句，按第廿八趟自己的实拍就地改掉）。
更深的一档在 **§12**（同日第廿九趟，三层形状）：**`subDirCount` 数的是整棵子树**（三层形状下直接
子级 1、子树 2，九个读数全是 2），而**文件那两格同形状三趟给了三档**（`1/64`、`1/64`、`2/128`，
其中 `2/128` 连本次设计的两个候选值都不是）⇒ 三格**不是同一个口径的三面**，落码仍只交回数字。

⭐ **§10 第一条（幂等）已由同日第卅趟换成读数**（**§13**）：对**同一枚 `fileId`** 打第二发
`batchTrash` ⇒ 上游回**同一句** `code:"0000" + success:true`，而回收站里**还是那一条**
（条数不变、`trashedAt` 逐毫秒仍是**第一发**那一条）⇒ 重复点名今天没有"多出一条"的读数。
那一趟自己划的边界里有一条"对象只测了**空目录**与**文件**两型" ⇒ **§14**（同日第卅一趟）补上
**非空目录**那一型：同一枚目录点名两次，两趟都是 `0/1/1`，里面那枚子文件在两遍回读里**都没单列**
⇒ 上面那句从"两型"升成"**清理链会点名的三型都测过，读数一致**"（仍带 §14 自己那四条边界）。

## 2. 请求侧：第一次真打

`POST {BasePersonalKD}/hcy/recyclebin/list`，体只有两枚嵌套键（出处是
[`apiServer.js`](apiServer.js) 的 `getVirDirInfo`，那里它就叫"回收站相关接口"）：

```json
{"pageInfo": {"pageCursor": "", "pageSize": 100}}
```

- **第一页发的是空串**，不是省略这一枚键（App 那句 `item.nextPageCursor || ""`）。
  ⚠ "省略这一枚键会怎样"零样本，本仓没有拿它试过。
- `pageSize` 只在 **100** 这一档验证过 ⇒ 换面值**未测试**。
- 头画像沿用同族 `batchTrash` 那一档（web 渠道 + `op*100`，旧 TS `apis/file.ts:114` 写死的画像）。
  **本轮实测它认**：两号五趟全部 `code:"0000"`，没有一档被头画像挡下。
  ⚠ 这一句是"list 认这一档"的读数，**不**覆盖同族另三口。

## 3. 响应侧逐字形状（本仓第一份，此后是这一族的形状基准）

信封与同族 `file/create` 一致：载荷在 **`data`**（不是 `result`），`code` 是字符串 `"0000"`。

```
data = {
  items: [ 条目… ],
  nextPageCursor: null | <长度 104 的串>
}
```

| 格 | 读数 |
| --- | --- |
| 条目数组挂在哪 | `data.items`（探针按形态扫"哪条路径下挂着对象数组"，五趟都只有这一处） |
| 总数那一格 | **没有**。五趟都没读到 `total` / `count` 类键 ⇒ "回收站一共多少条"这一问这一口答不了 |
| 游标 | `data.nextPageCursor`：满页时是长度 104 的串，最后一页是 **`null`**（键**在**、值为 null）⇒ "键缺席"是第三种情况，接口层单独用一格记（`HasCursorField`） |
| 顺序 | `trashedAt` **倒序**（新的在第 0 项）。账号 0 首末：`15:06:59` → `2025-05-06`；账号 1 首末：`14:27:28` → `2026-09-12`。⚠ "上游保证倒序"没成文，只是复述实拍 ⇒ 排序不要依赖它 |

**条目 14 枚键**（folder 型与 file 型同键集，差在两格的值型）：

```
category createdAt fileId mediaMetaInfo name remainingTime size
thumbnailUrls trashedAt trashedDirStatistics trashedReason type updatedAt userTags
```

| 键 | folder 型 | file 型 |
| --- | --- | --- |
| `type` | `"folder"` | `"file"` |
| `size` | `0` | 真实字节数（见过 `64` / `597` / `5411` / `5412`） |
| `thumbnailUrls` | `null` | 数组，一项里含 `{style:str<5> url:str<644>}` ⇒ **本层不读** |
| `trashedDirStatistics` | 对象 `{subDirCount, subFileCount, totalSize}` | `null` |
| `trashedReason` | 见过 `"userTrashed"` 一档 | 同 |
| `remainingTime` | 见过 `14` 与 `0` 两档（`0` 在账号 1 第二页那批**更早**的条目上） | 同 |
| `name` | 长度 23~25 的串（探针只念我方条目的值） | 同 |
| `userTags` | 数组，5 项 `{key:str<12> value:str<9>}`；第二页也有 1 项 `{key:str<6> value:str<4>}` 的 | 同 |
| `category` | 长度 5~6 的串 | 同 |
| `mediaMetaInfo` | `null` | `null`（探针两份形状读数里都是 null） |

⚠ `category` / `userTags` / `mediaMetaInfo` / `createdAt` / `updatedAt` **接口层一律不解释**：
本仓没有任何成文说它们是什么，落成字段等于把猜测固化成接口层。

## 5. ⭐ 延迟那一格怎么测（本文最要紧的一条口径）

探针里两遍回读之间**唯一的动作是等**（`liveProbeBinWait = 20s`，中间一枪都不发），
账号 0 的 run2 逐字读数：

| 本趟那枚（按**整名**） | 当场那一遍 | 等 20s 之后 |
| --- | --- | --- |
| 目录 `asign-binlistdir-d4bcbc1b` | **false** | **true**（第 0 项，`trashedAt=2026-09-26T15:15:56.161+08:00`） |
| 里面的文件 `asign-binlistkid-76008198.png` | false | false |
| 第 1 页条数 | 33 | 34（差 1） |
| 游标 | `null` | `null` |
| 闸门 | 4 页 / 最多 400 条，**未截断** | 同 |

⇒ 两条结论：
1. 这一口有**秒级不回**：`batchTrash` 被上游认了之后，`recyclebin/list` 当场那一遍可以不列它。
   **「当场回读说没有」不是「没进回收站」的判据** ⇒ 判"进没进"只认**等过之后**那一份。
2. 目录进了（等后 `true`），那枚文件**两遍都不在**，且游标 `null`、闸门未截断 ⇒
   **整棵子树只记成一条，子文件不单列** ⇒ R7 那句"清理链接目录不需要把子文件也记进名单"
   现在**有回收站侧的读数**，不再只靠"两处都不再列它"推。

配套的第三格：账号 0 只读复跑（reread0）里 `binlistdir-` 命中 `true`、`binlistkid-` 命中 `false`
—— 与上表**隔了一趟**仍然一致 ⇒ 这一档不是当场那一遍的巧合。

顺带：这条延迟为第廿六趟 A 趟那格"删后根目录**仍列**那枚目录"提供了一个**同族解释**（回读侧滞后）。
⚠ 这一句只是**假设**：A 趟那一份是**网盘侧** `file/list` 的读数，与这里的 `recyclebin/list`
不是同一口，那一趟也没有"等一遍再读"之外的时间戳 ⇒ 成文里仍标 `待验证`，不当结论用。

## 6. 命中怎么认：中段会被同族残留骗过（run1 → run2 的修法）

run1 那一趟打的判读是"两遍一致且**都在** ⇒ 实测"，读起来成立、其实是**错的**：
探针按名字**中段**（`binlistdir-`）认命中，而同一族复跑两次时，回收站里**同时**有
上一趟那枚同中段的残留与本趟刚删的那一枚 ⇒ 当场那一遍命中的是**上一趟的残留**。

修法（已落码，带纯单元测试 `TestLiveProbeScanBinEntryMatchesExactNotInfix`）：
- **判定行**（"本趟那一枚在不在"）按**整名**（`exact`）；
- **族账行**（"这一族在回收站里留了几条"）仍按**中段**（`mine`）。

run2 那行逐字读数把两格分开念得很清楚：
`⑥ 命中对照（当场 / 等后，按本趟整名）：目录=false / true；文件=false / false`
`⑥ 同族残留这一格（按中段，含更早趟那几枚）：目录中段=true / true；文件中段=false / false；条数 当场 33 / 等后 34（差 1）`

## 7. 本轮堵上的一处泄漏口子：错误文本里的预签名 URL

**出处是读代码，不是这一轮跑红过**：`target/s27probe/` 那五份 stdout 逐份 `grep` 过，
一个 `http(s)://` 都没有（账本里 `PUT` 那一格早就是占位）。但
`internal/io/client.go` 在传输层出错时会把 `http.Client` 的**原始错误**包进错误串，
而 `PUT` 那一枪的原始错误形如 `Put "https://<对象存储主机>/<对象键>?X-Amz-Signature=…": dial tcp …`
⇒ **只要那一枪在传输层失败一次，整条一次性签名入口就能从错误文本里出去**。本轮探针会发 `PUT`，
所以这条路必须先堵住再跑。

修法：探针侧所有错误都过 `binErr()` —— nil-safe + `sink.mask` + `liveProbeHideWriteEntry`
（把 `https?://…` 整段换成占位）。反向测试：`TestLiveProbeHideWriteEntryKeepsPresignedURLOutOfOutput`
（把 helper 改成 `return text` 它就红）。

同族读数的一条修正：探针曾念"没读到名字含 cursor 的键"，而实拍是 `nextPageCursor: null`
—— 分类代码把**键名**判断放在**类型**分派之后，`null` 那一档被类型分支吃掉了。
已把键名分类挪到类型分派**之前**，并让游标那一行分别念 `null ⇒ 上游用它说'没有下一页'` / 空串 /
`值长 N，值不打印`（`TestLiveProbeScanBinEntry…` 一组 + run2 / reread1 两份输出为证）。

## 8. 接口层落码口径（本文 §3 是唯一形状出处）

### 这一问为什么不是学术题

而"同一枚被点两次名"这件事在真实链路上有三条来源：任务被重复触发、组合链里两条链上传了同一枚产物、
用户连点两次清理。三档后果各自不同：第二发**报错** ⇒ 播报里会出现"清理失败"而其实东西早就进了回收站；
第二发**又多记一条** ⇒ 用户回收站里同名两份，还原时也是两份；第二发把那一枚**弄没** ⇒
"重试一次 = 用户的东西从回收站消失"，后果最重。今天哪一档都不是推断：见下面那张表。

### 形状：两枚对象 × 各两发 + 三遍回读

每趟造两枚：一枚**空目录** `asign-retrashdir-<hex>`、一枚**根目录文件** `asign-retrashfile-<hex>.png`
（两型 = 清理链会点名的那两型）。每枚**各打两发** `batchTrash`（第一发送它进回收站，第二发才是本趟要问的那一枪）
⇒ 一趟 4 发写。回读三遍：**⓪ 删之前**（对照：证明这一枚整名本来不在册）→ 第一发 → **等 20s** → **② 第一发之后**
→ 第二发 → **等 20s** → **④ 第二发之后**。判据是**条数**（同一把尺：解析器翻页按**整名**数，#196），
两枚对象只是同一判据的**两个样本**，不是"一次动两问"（那一条纪律来自第廿六趟，坑表 #194 同族）。
两遍之间**唯一动作是等**，一枪都不发（§5 那条"秒级不回" ⇒ 不等就读，判据不成立）。

### 方法格：判定函数换对象型复用时，"预期"也跟着换

`liveProbeRetrashWord` 那批短标里 `[幂等=仍一条]` 的成立条件是"② 与 ④ 同数"，这一格在
非空目录上**照用**没问题；但**子文件**那一格不能照抄 —— 它在两遍都该是 `0`，
"两遍同数"这一档对它是**默认态**而不是结论。所以那一支的档位是按"④ 比 ② 多"给结论的，
且"两遍同数且非零"单独一档（那意味着**第一发之后它就单列了**，与 R7 相反 ⇒ 要回去复核 R7，
不在本趟改口径）。落地句：**同一把尺换测量对象时，先问一遍"哪一档在新对象上是默认态"**，
默认态不能当判据。
