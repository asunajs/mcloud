## 0. 一句话结论

**四枪全部打得通，而它们里最要紧的一格是"那道门今天永远不开"。**
①′ 用邮箱会话换到 `{account(24) token(201) userDomainId(19) userid(12)}`，DES 解出来是
11 位、形如手机号 ⇒ 我们那份按旧 TS 文字形状写的路径**与真实体对得上**。
②′ 不带任何鉴权头，身份全靠 body 里那枚 RSA 密文 ⇒ 上游**认**（对照枪：`585` / `106` / `1020`
都回 `code:"0" + result{…}`），而 `1028` 自己与一枚造出来的 `999999` 回
`code:"501" / msg:"任务不存在"` ⇒ 那句"任务不存在"是**按 taskId 给的**，路由与身份都活着。
③′ 三趟分别 69 / 66 / 52 行 `data:`，累出三句互不相同的模型原话。④′ 与 ②′ 同形。
**整条玩法（走生产编排）三趟都是"发过枪 = true、失败 0 条"。**

## 1. ①′ `disk!…queryUserToken`（邮箱会话 → AI 域凭据）

直发那一档（构造 + 发送 + `ParseAIWorkbenchUserToken`）与生产路径**同一份请求**，读数一致：

- `HTTP 200`，形状：
  `code="S_OK"`、`summary=str<0>`、`var={data={code="0000", message="请求成功", data={…}}}`
- 里层 `data` 的键与类型（**只有键名与长度**）：
  `account=str<24>`（DES 密文，解出 11 位手机号）、`belongsPlatform="2"`、
  `cutoverStatus="1"`、`provCode=str<2>`、`routerInfo=[49 项]`（第 0 项
  `{hashName=str<6> httpUrl=str<38> httpsUrl=str<39> modName=str<8>}`）、
  `token=str<201>`、`userDomainId=str<19>`、`userid=str<12>`
- 解析结果三格：手机号长度 11 / 形如手机号 = true、`token` 长度 201、`userDomainId` 长度 19；
  拼出的 `Authorization` **整串**长度 302（值不落档）。

⇒ 与 `ParseAIWorkbenchUserToken` 里那份"旧 TS 写的路径"**逐键一致**，不需要更正。
⚠ 它也没有回"手机号之外的第二种 `account` 形状"—— 那一格仍无样本。

## 2. ②′ 状态查询：不带鉴权、RSA 自证身份**被认**

请求侧（这一格是"我们发出去的东西"，念的是**形状**）：

| taskId | 真实读数 | 我们的门 |
| --- | --- | --- |
| **1028**（本玩法自己） | `code="501" msg="任务不存在"`，**无** `result` | `EnvelopeOK=false`、`GatePass=false` |
| 999999（造出来对照） | 同上 `501 任务不存在` | 同上 |

## 3. ⚠⚠ 那道门在真实读数下**永不成立**

旧实现的两句话是 `cs?.code === 0 && cs.result` 与 `taskStatus === 1 && cloudStatus === 0`
（`runners.ts:363-376`）。真实体三格全是**字符串**（`"0"` / `"1"` / `"0"`）⇒
JS 的 `===` 不做隐式转换 ⇒ **同一份体在旧实现手里同样不成立**。

于是本轮的处置是**钉住而不是改**：

- `ParseAIWorkbenchTaskStatus` 的 `EnvelopeOK` / `GatePass` 继续按**严格数字**判
  （用例 `TestParseAIWorkbenchTaskStatusRealBodiesKeepGateClosed` 逐字用这三份真实体）；
- 编排层因此**永远走**"仍发对话"那一档，播报落在
  "AI 工作台前置状态读不出门 … ⇒ 照旧实现仍发对话"；
- ⚠ **不放宽**的理由：放宽等于由我们替用户决定"这一条少发一次**写**"，
  而它与旧实现的行为也不再一致。要不要按"字符串也认"改门 = **待拍板问句**，不是缺陷。

反向验证（三次变异，均已还原）：把门改成接受字符串 ⇒ 新增那条真实体用例与
`TestParseAIWorkbenchTaskStatusGateIsStrictNumbers` 同时红；把 ③′ 判据里的
`|| read.Answer == ""` 删掉 ⇒ "有事件但内容为空"那一档红；把 `if len(chatProblems) > 0`
改成恒真 ⇒ ②′④′ 计数与时序红。

## 4. ③′ 对话（**这一枪是写**）+ ④′ 链尾复查

- ③′ 三趟：`data 行数` = 69 / 66 / 52，末条 `code=0000`、`message="请求成功"`，
  `sessionId` 是 **19 位数字**（值不落档），模型回话三句互不相同
  （"你好，请问有什么我可以帮您？" / "你好！我是灵犀，请问有什么可以帮您？" /
  "你好，我是灵犀，请问有什么可以帮您？"）
  ⇒ "正序走 + `outContent`/`content` 两格同累一个串"这套读法**至少不是空转**。
- ④′ 与 ②′ 同形（同一号同一 taskId，仍是 `501`）。
- ⚠ **本轮真跑跑出来一个缺陷并修掉了**：`workbenchReadLine` 原先把 `sessionId` 的**值**
  念进播报 ⇒ 它会进事件流、`runs` 日志与推送正文。修法：**只念长度**
  （`sessionId 长度=19`），夹具用一枚可断言的合成标识把这一格钉住
  （`internal/app/task_matrix_workbench_run_test.go` 的 `…AsksOnce` 那条）。
- 整条玩法走生产编排（`runWorkbench`）三趟都是：`发过枪 = true`、失败 0 条。
- 产物面：③′ 在 AI 工作台那边**留下一条会话记录**（本仓零实现"删会话"那一口）⇒ **不可回滚**。
  它不写网盘，所以与 `CloudFileIDs` 那条清理链无关。
