## 2. 第二发：**只读**走完整棵树（深度 ≤2）

小结那一行逐字：

```
小结：列了 58 个目录（上限 60，深度上限 2，没列完的不算找不到）；type 读数 = file→735 folder→73；
     被当成目录去列的那些枚的 type = folder→57；我方前缀命中 3 枚；非我方 .pdf 1 枚
覆盖：队列里还剩 0 枚没列（上限 60 用掉 58）；粗筛漏掉的 folder 0 枚（名字里带点的目录，本发没进去）
```

⇒ 这一发的对照面是**走完的**，不是"撞到上限后截断"（这是"没找到"值不值得信的关键一格）：
808 项、58 个目录、根目录到第 2 层全部列过（每目录只看第一页）。

- **我方前缀（`asign-`）命中 3 枚，全在根目录**，都是 `.png`（`asign-xxxxxxxx.png` 那种默认名）。
  转换产物**没有**以任何 `asign-` 名字出现在这棵树里。
- **不是我方前缀的 `.pdf` 只有 1 枚，也在根目录**，`createdAt=2015-02-07T21:24:32.000+08:00`
  （探针当场换算：**距今 6,117,894 分钟 ≈ 11.6 年**）⇒ 它**不是**这一轮的产物。
  ⚠ 这一格第一次跑读数是一句 `距今 29816095814 分钟`（≈ 56,700 年），那是**我们自己**把
  "请求头用的微秒"当成"毫秒"去减（坑表 **#183**）—— 换算错了的读数比没有读数更危险，
  因为它看起来像一个"很老的 PDF"这种**能自圆其说**的结论。

## 3. `file/list` 里本层不读的那两格，第一次有值

生产解析器 `upstream.ParseCloudFileList` 只取 `fileId` 与 `name`；`type` / `size` /
`trashedAt` 三枚**本层不读**（成文在 `app-mail139-samples.txt` §9 第 5 点）。这一发裸读了一次：

| 格 | 实拍 | 形态 |
| --- | --- | --- |
| `data.items[].type` | **只有两档**：`file`（735 枚）/ `folder`（73 枚） | ⚠ **小写字符串**，不是数字（与坑表 #176 同族：这一族常回串） |
| `data.items[].createdAt` | 例：`2015-02-07T21:24:32.000+08:00` | ⚠ **RFC 3339 带时区的串**，不是毫秒数 |

⇒ 被我们当目录去列的那 57 枚，`type` **全是** `folder` ⇒ "名字里有没有点"这一记粗筛在这一发里
与 `type` **一致**（不代表它总是等价；粗筛漏掉的 `folder` 当场数了：0 枚）。
⚠ 这两格**没有**因此进生产层：本仓今天没有任何一处按 `type` 分流，要加分流得先按 AGENTS.md §1.5
登记并说清"读了它用来判什么"。

## 4. R36 收到哪、剩下哪几格

- **收到**：`转换 = 在网盘里另存一份（且名字带我们的前缀）` 这一档，在"根目录 + 深度 ≤2 全树、
  写入后约 8 分钟"这个对照面内**没有支持样本**。⇒ 1014 的播报**保持**"念素材已上传 / 转换被认"，
  仍然**不**念"网盘里干净"（下面三格没排除）。
- **仍开的三格**（都要么需要 App 侧看一眼、要么需要新的只读面，都不是"再跑一遍这一发"能答的）：
  ① 产物**不落网盘**、只落邮箱侧（`mail.10086.cn` 那一台今天只剩 `/login/inlogin.action`，
  本仓没有邮箱侧文件列表口 ⇒ 探针打不到）；② 产物落在**深于第 2 层**的目录（本发上限）；
  ③ 产物**晚于 8 分钟**才出现（异步）—— 这一格只能"过一阵再只读一遍"，两分钟的成本，不需要重跑写。
- ⚠ 这三格**都不构成**"该给 1014 加清理"的理由：清理要有 `fileId` 才删得着，而 ⑥ 的响应
  本仓只判 `code`（零 `var` 样本）。在没有 `fileId` 的情况下加"按名字猜着删"= 可能删掉用户
  自己那份 2015 年的 PDF（这一发恰好念出了它的存在）。

## 5. 顺带：我方前缀的 3 枚残留（R37ⓒ 的第一条读数）

`asign-*.png` 是上传那几族的**默认名**（`CloudUploadNamePrefix` + 4 字节随机 hex + `.png`，
见 `internal/app/cloud_upload.go`），585 / 106 / 522 几条链**共用**这一种形状 ⇒
**按名字分不开是哪一条链造的**，这一格只能说"有 3 枚没被清"。
它同时是 R37ⓒ 的第一条真实读数（原先那一格只能靠 `batchTrash` 那句上游原话）：
**AI 相机那一族写进网盘的图，链尾没有删干净**（⚠ 归因到"哪一条链"仍需一次同型对照：
跑一条链前后各走一遍树，看枚数动没动）。

## 6. 探针自身的边界（别把这两发读成它没说的事）

1. **只读那一发是"事后 10 分钟"的快照**，不是持续观察 ⇒ 它把"异步晚到"削弱到"8 分钟内没出现"，
   没有排除它（§4 第 ③ 格）。
2. **每个目录只看第一页**（`pageSize=100`，本族与生产同档）⇒ 一个装着 300 项的目录里，
   后面 200 项**不在**对照面内。这一发的两枚 100 项目录（深度 1 与深度 2 各见过）就是这种口子。
3. **回收站里的不算** ⇒ "清理后回到 31 项"同时兼容"素材在回收站里躺着"（那是**预期**，
   `batchTrash` 的语义就是移进回收站）。
4. 带写那一发**只跑了一次**（账号 0）。同一趟内三遍回读是它的判据；**跨账号同型**这一格
   本轮**没有**补，因为补它的代价是往第二个测试号网盘再写一份 PDF + 请求一次转换，
   而它只会重复"根目录不多一枚"这一条读数（不做无理由的写，见 `capture-guidelines.md`）。
