## 0. 一句话结论

- **R26 收口**：`doTask` 第一次真打 ⇒ `HTTP 200` + `{"code":0,"msg":"success"}`，
  两号逐字同形，`code` 是**数字**。判定已按打卡那一族同一套接上（见 §3 与坑表 **#190** / **#191**）。
- **R24 那一格**：同一趟里**三遍**拉表（动手前 / 复查 / 跑后回读），两号各
  **0 条变了** ⇒ "分钟级滞后"这一档**已排除**；"永不翻 vs 隔天翻"仍要靠**跨日**回读（§4）。
- **跑出来两处措辞缺陷，都已修**：① 小结把"一枪没发的缺前置"和"发出去被打回"
  混成同一句"上报失败"（坑表 **#189**）；② 入口上报那一发的失败文本把上游原文整个
  丢掉（坑表 **#190**）。见 §5。
- **顺带登记成待拍板的一格**：逐条播报里 `播报[2] 失败 <名> <id>` 那一档念的是
  "打过、复查未认"，**不是**"这一发报错了" ⇒ 该念什么见 **Q49**，本轮没改（§5 末尾）。

## 1. 复跑命令（读数只在这些日志里，本文件是摘要）

```
cp data/mcloud.db target/s24probe/probe.db        # 副本：这一族会写库（runs 表）
: > target/s24probe/device.txt                    # 设备档案：路径必须已存在
MCLOUD_LIVE_PROBE_DB="$PWD/target/s24probe/probe.db" \
MCLOUD_LIVE_PROBE_ACCOUNT_INDEX=0 \
MCLOUD_LIVE_PROBE_DEVICE_FILE="$PWD/target/s24probe/device.txt" \
MCLOUD_LIVE_PROBE_CONFIRM='确认写真实上游' \
go test ./internal/app/ -run TestLiveProbeRunAccountFull -v -timeout 600s
```

⚠ 两枚路径**必须绝对**（`go test` 的工作目录是包目录；相对路径会静默造出一份空档，
读数全废 —— 出处见 [`app-mail139-samples.txt`](app-mail139-samples.txt) 抬头那条）。
⚠ 这一趟**会写真上游**：打卡、入口上报、邮箱备份那一发（404 所以什么都没写成），
并按"除兑换外全部实测"的口径授权；这一趟**没有**触发网盘上传（两号当天没有可传的条目，
所以清理那一节念的是"没有要清理的 / 枚数 0"）。
换 `MCLOUD_LIVE_PROBE_ACCOUNT_INDEX=1` 跑另一个号。

## 3. R26：`doTask` 那一发，逐字（值级掩码后）

```
这一发带的 deviceId 长度 89（值不打印）
枪[4] GET mrp.mcloud.139.com/market/signin/page/doTask
      查询串 client(值长 3) deviceId(值长 89)
      ⇒ HTTP 200，体形状 ={code=0(数字) msg="success"}
入口上报交回：没有错误
```

- 查询串**只有这两枚键**，顺序 `client` → `deviceId`，与 [`MrpDoTaskRequest`] 构造的逐字一致
  ⇒ 不是"迁移抄错了路径"那一档。
- `code` 是**数字** `0`，与打卡那一族四条实拍同形 ⇒ 走同一份解析器（[Envelope.EnsureOK]），
  不需要为这一口单开解码。
- ⚠ 这次真打**只回答"上游收不收这一枪"**（收，且回 0）。它**不**回答
  "回了 0 算不算把这条任务记成做了"—— 那一问见 §4。
- ⚠ 同趟的 `task/click` 那 6–7 发在**修复打印器之前**输出，读数是 `code="0"`
  这一**两可**形态（旧打印器把数字与字符串都写成带引号的样子）。
  不影响判定（`asInt64` 两条分支都认，而那几发都被计成"上报成功"），
  但**别把打卡那一族的 `code` 类型写成已实测**。
- 失败码这一口**仍零样本**：今天的判定只是"非 0 即失败、缺 `code` 不判失败"，
  不给任何码编语义。

## 4. R24 剩下那一格：三遍拉表的差集

同一趟里读三遍全表（`动手前` → `RunAccount` 内部的复查 → `跑后回读`），逐条比对
`state / currstep / process / enable` 四个面值：

```
号一  拉表[动手前]：16 枪 / 去重前 35 / 去重后 27 / 待做 10 / 没读到的组 0
      差集读数：两遍都在的 27 条里**变了 0 条**，其中本趟没动过的 0 条；只在跑后出现 0 条、只在跑前 0 条
号二  拉表[动手前]：16 枪 / 去重前 32 / 去重后 24 / 待做 9  / 没读到的组 0
      差集读数：两遍都在的 24 条里**变了 0 条**，…（同上，全 0）
```

⇒ 读数确定的那一格：**分钟级滞后不成立**（跑完立刻回读，当天打过卡的那些条仍
`state=WAIT` —— 号一是 548 / 550 / 551 / 1029 / 1078 / 1079 与 1005 那条玩法，
号二是 548 / 550 / 551 / 1057 与 1005 / 1020；两号的复查那格分别是"没认 7 / 没认 6"）。
⇒ 读数**不能**确定的那一格：这些枪**当天晚些时候 / 隔天**会不会翻。要核它得隔一天
再跑同一趟并只比差集（任务清单里那条跨日复跑，与"念出上游另存的转换产物"那一趟合并做）。
⚠ 也别反过来读成"打卡永远没用"：`process` 那一格当天在**别的**任务上是动过的
（见 `docs/status.md` 第十一趟那一条，只有 522 在动）。

## 5. 界面上的原文（这一族唯一"用户看到什么"的样本）

号一小结（`runs.summary` 与终局事件同一句）：

```
任务表 27 条（待做 10 条）；本次上报 7 条（打卡 6、玩法 1）；1 条上报失败；
复查：认下 0、没认 7、此前已完成 16、仍待办 2
```

号二小结：

```
任务表 24 条（待做 9 条）；本次上报 5 条（打卡 4、玩法 1）；2 条上报失败；
复查：认下 0、没认 6、此前已完成 14、仍待办 2
```

那几条"失败"的处置行原文（号二两条，两号都有 434 那一条）：

```
处置 #434  [month] 分享文件领好礼5/7 ⇒ 专属玩法 runner="分享一个文件并立刻取消"
          原因="currstep 不为 0 ⇒ 按旧实现的门不发前置那一发，只跑玩法"
          错误="没有可分享的文件：这一趟前面没有任务往网盘传过东西 ⇒ 分享那一半没做"
处置 #1020 [month] 完成一次邮件转存 ⇒ 专属玩法 runner="邮箱资产备份"
          错误="邮箱备份（⑧）失败：不存在: HTTP 404"
```

⚠ **上面那两行就是修掉的缺陷本体**：小结那一句"2 条上报失败"底下，
434 一枪都没发（§2 账本里它名下零发），1020 是真发了 ⑧ 被打回 404。
两句话对用户是**不同的下一步**（前者是表序 / Q41，后者是 R35 那一次真机取证），
所以从这一版起小结按"出过网没有"分三档措辞：

| 计数 | 小结念的那一句 |
| --- | --- |
| `Failed=1 / FailedNoShot=1`（号一那一档） | `1 条没做成（一枪都没发：缺前置）` |
| `Failed=2 / FailedNoShot=1`（号二那一档） | `2 条没做成（1 条发出去了、1 条一枪没发：缺前置）` |
| `Failed=1 / FailedNoShot=0` | `1 条上报失败`（维持原措辞） |

判据是 `TaskStepRecord.Fired`（"出过网"，**不是**"上游认了"），
用例：`internal/app/task_matrix_summary_line_test.go` +
`TestTaskMatrixRunShareSaysNothingWasSentWhenTheGateBlocksIt`。

逐条播报那两层（分节标题 + `已完成 / 失败 …` 行）当天也第一次走完全程，其中
`播报[2] 失败 开启备份领好礼 548` 这一档的含义是"打过、复查未认"（§4），
**不是**"这一发报错了" —— 打卡那一枪的响应是 `HTTP 200 / code=0`。
⚠ 这一格今天仍是**措辞**问题（用户读到"失败"会以为枪没发出去），
已登记为 **Q49**，不在本文件里替它定。
