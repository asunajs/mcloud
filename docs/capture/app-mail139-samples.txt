## 0. 一句话结论

**换会话那两枪是真的能用，打卡那两枪今天上游不认。** ① 换到票（长度 42）、
② `inlogin.action` 回 `HTTP 200` + `code="S_OK"` 并在 `var` 里带着 `sid`(38) 与 `rmkey`(16)

1. **解析器不用改**：`code` 在顶层、`sid` / `rmkey` 在 `var` 里 —— 与

## 3. ③ 为什么不是"我们写坏了"（三档对照）

| 档 | 变量 | 结果 |
| --- | --- | --- |
| A | 带 `authorization`（生产代码走这一档） | `HTTP 404`，体 3755 字节 HTML |
| B | 不带 `authorization` | **同上，逐字节同形** |
| C | 两枚值**裸拼**进 URL（照旧 TS 的字面形状，绕开 `PercentEncode`） | **同上，逐字节同形** |

⇒ 排除了解释「头没给对」与「值被百分号编码编坏了」两种。
剩下的可能探针**分不开**，都还挂着：这条路径要吃别的头（`Referer` / `User-Agent` /
`Cookie` 里的某一枚）、要吃 POST 而不是 GET、或者它在厂商侧就不是这个地址了。
⚠ 这三条都只是**待验证**，本文件不写任何一条为结论。

`docs/capture/` 里 ③④ 两条**至今零命中**（2026-09-25 按 `autologin.action` 与
`taskClickV2` 逐份扫过）⇒ 上面这些可能性的判据只能来自**真机那一发**（§6）。

## 4. ④ 的 404 归因到了"那一条路由"，不是整片入口

④ 回的是 **JSON** 的 404（`{code:"404", msg:"访问资源不存在"}`），③ 回的是 HTML 的 —— 两句
形状不同，说明 ④ 这一枪被**应用层**接住了。但"应用接住"还差一步归因，所以带了一发
只读对照枪 ⑤（同一台 `caiyun.feixin.10086.cn:7071`、同一个 `/ycloud/` 前缀、另一条路由）：
它回 `HTTP 200` + `code="0" msg="success"`。

⇒ **入口活着，挂的是 `signin/task/taskClickV2` 这一条路由**（或者它吃的是别的形状）。
⑤ 顺带读到 notice 那一族的实况（同一份输出）：
`taskOneInfo={cloudStatus="2" sum="200" taskStatus="3"}`、
`taskTwoInfo={cloudStatus="0" progress="2" sum="100" taskStatus="2"}`。两点：
① 两槽的**键集合不同** —— `progress` 只出现在第二槽，第一槽没有 ⇒ 与 `internal/upstream/app_notice.go`
里"槽内字段全部可选"那份解析一致（那一格此前只有夹具依据）。
② 这一发**不推进 R1**（"`cloudStatus` 哪个值是未领"）：读到的仍是 `2` 与 `0` 两档，
`1` 那一档到今天**一次都没出现过** —— 与 R1 记着的读数面（同日四槽 ∈ {0,2}）逐字同型。

## 7. 探针自身的边界（别把它当回归测试）

`TestLiveProbeMail139Family` **没有断言**：它只把上游回话念出来（文件头成文了这条）。
所以"它 PASS"只代表"枪发出去了、输出没崩"，**不代表**这一族可用。默认档是 `t.Skipf`
（四个环境变量任一为空），门禁跑不到它；`MCLOUD_LIVE_PROBE_CONFIRM` 的确认串是
一句人话而不是 `1`，为的是"顺手 export 一个真值"打不到真上游。
**探针这一形态（可复用仪器 vs 一次性用完删）是 agent 侧默认、非用户要求**，
已写成问句挂在 `docs/pending-decisions.md`。
