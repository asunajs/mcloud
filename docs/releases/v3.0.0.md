# mcloud 3.0.0

第一个**正式版**（前面几个都是 rc 预览版）。这份说明是相对**上一个正式版 `v0.1.0`**（2026-09-29；仓库里只有 tag，没有对应的 release 页）的重点摘要，不是全量清单 —— 中间那几版 rc 的改动也算在这一版里；下面按"你能看到什么"分组写，不列代码提交。

![mcloud 3.0.0 一览](https://github.com/asunajs/mcloud/releases/download/v3.0.0/v3.0.0-card.png)

## 拿到就能用

下载对应平台的包，解开就是**一个可执行文件**（Linux 上是 `mcloud`，Windows 上是 `mcloud.exe`；命令行和网页服务合并进它了）：

| 你的机器 | 选哪个 | 下载的文件 |
|---|---|---|
| Linux（Intel/AMD 64 位） | `x86_64-unknown-linux-gnu` | `mcloud-v3.0.0-x86_64-unknown-linux-gnu.tar.gz` |
| Linux（同上，但系统很老 / 缺库） | `x86_64-unknown-linux-musl`（静态，不挑系统） | `mcloud-v3.0.0-x86_64-unknown-linux-musl.tar.gz` |
| Linux（ARM 64 位，如服务器 / 树莓派 64 位） | `aarch64-unknown-linux-gnu` | `mcloud-v3.0.0-aarch64-unknown-linux-gnu.tar.gz` |
| Windows | `x86_64-pc-windows-msvc` | `mcloud-v3.0.0-x86_64-pc-windows-msvc.zip` |

包名就是 `mcloud-v3.0.0-<上面那个三元组>`，Windows 那份是 `.zip`；每个包旁边还有一个同名的 `.sha256`（校验和文件）。这一版一共 8 个资产。

> ⚠ **Linux 上拿不准就下「静态」那份**（`x86_64-unknown-linux-musl`）：libc 与 OpenSSL 都静态链进去了，不依赖系统的 glibc 和 libssl，任何 Linux x86_64 都能跑（CentOS 7 / Debian 11 这类老发行版也一样 ✓）。
> 另一份 x86_64（`-gnu`）是动态链的，**要求 glibc ≥ 2.39 且装了 `libssl3`** ——
> 在更老的发行版上会报 `version GLIBC_2.39 not found` ✗。

**这一版没有 macOS 预编译包**：只出上面那 4 个目标。CI 的 macOS runner 太贵，已经从发布矩阵里去掉了，macOS 用户请自行从源码编（`cargo build --release`）。`v3.0.0-rc.4` 那一版是有 `aarch64-apple-darwin` 包的，别拿它当这一版的替代。

**第一次跑**：直接敲 `mcloud`，它会把网页服务起在 `http://127.0.0.1:3000`，用浏览器打开即可。
⚠ 多用户、想给别人用 ⇒ 看 `docs/usage.md`（WebUI 篇）；只有命令行的机器 ⇒ 看 CLI 篇。
⚠ 详细说明见仓库的 `docs/usage.md`（本文件只是"这版变了什么"）。

## Docker / 容器（Linux）

不想装运行时依赖、想用容器跑：仓库根目录有 `Dockerfile` 与 `docker-compose.yml`，`docker compose up -d --build` 起服务（十几分钟，在**本机架构**上原生编）。镜像里是静态 musl 二进制（不依赖 glibc / libssl）加 `ca-certificates`、`tzdata`，数据全在命名卷里；端口默认只发到宿主机 `127.0.0.1:3000`。要局域网 / 公网访问、挂 HTTPS、备份升级、故障排查，见 `docs/docker.md`（README 的 §4 也有一份简版）。

CI 出的那份在 ghcr 上，一个标签含 `linux/amd64` 与 `linux/arm64` 两份，`docker pull` 按机器自动挑：

```bash
docker pull ghcr.io/asunajs/mcloud:latest
```

两点要说清：

- `docker.yml` 已经改成**不跟 tag 自动跑**（提交 `b1023f7`：一次要起两台 runner，太吃 Actions 额度），所以 **3.0.0 在 ghcr 上有没有对应镜像属于待确认**。
- 这一层本机没验过（开发机没装 docker，`docker build` 跑不起来），以 `docs/docker.md` 为准。

## 这版新增 / 修好的（重点）

### 直播小红花
- **修掉一个真问题**：口令以前会**误判** —— 弹幕里的入场、送礼、点赞消息被当成口令投上去（日志里那种"无效口令"）。现在按上游真实字段区分事件与口令，**未知类型一律放行**（宁可多投一条废口令，也不漏掉真口令）。
- **每个口令都能看到**：日志里逐条记"这个口令领到了什么"，不再是只报总数。
- 默认「最多听多久」从 60 秒调到 **180 秒**。

### 云朵中心任务（App 里的任务）
- **列表改走新版接口（V3）**：以前会把**已经过期的任务**也列出来（548/550/1078 这类同名旧版），
  现在与 App 看到的一致；顺带补回了「小云互动礼」等之前缺的条目。
- **进度与文案照 App 显示**：能读到进度的写「完成进度 (17/31)」；状态词按上游给的那一档显示
  （「开启中」「下月再来」「去完成」），不再一律写成「待做」。
- **新做出来的几条任务**：「去云盘图书馆阅读书籍」(604)、「和AI助手对话」(609)、
  「加入一个知识库」(547)、「查看"我的账单"」(1029，含账单页与邮件上报那几发)。
- **两条 App 任务的修复**（都是在运行日志里看到 `FAIL` 才发现的）：
  「登录移动云盘云朵中心」(1017) 缺的是**页面初始化上报**那一发 —— 补上后整链是「上报 + 取入口页 + 打卡 `key=task2`」；
  「完成一次邮件转存」(1020) 的旧路径**实测 404**，改成 App 实拍的三发链（取落点目录 → 搜一封邮件 → 转存）。
  两条都在真机上两个账号各翻了一次。
- **上游已经做满的条目**：只领奖、不再重复运行，也不再误报失败。
- 「第一次跑本地记录，成功不跑二次」(434) 与「固定入口」那一档 (409/1005) 也补齐了。
- 通知那一口接上了：能读到「+100豆」与进度分子（该不该领的结论不在界面上摆）。

### 凭据（登录状态）
- **自动续**：每天到你设的钟点**检查一次**，该换才换；**不需要换就跳过**，并在定时页写明原因（"未到提前量，还剩 N 天"）。
- **每个登录用户各设各的钟点**（默认 `03:00`），互不影响。
- **手动一键刷新**：账号页每个账号一颗「刷新」、外加「刷新全部凭据」。手动是**强制**的 —— 不看还剩多少天，点了就换。

### 推送（通知）
- 规则回答"**怎么发**"，行为回答"**什么时候发**"；一个行为可以选**多条规则**。
- 每种面板行为都有单独的推送规则入口；默认**保守**（不刷屏），节流**不静默**（被限流会记日志）。
- 每日上限 `0` = 不限。

### 定时 / 编排
- 定时页现在能直接选**「编排」**作为目标（以前只能在编排页反向建），并能看出"跑的是哪一条编排"。
- 直播**自动定时**：按上游"下一场"时间自动设好（下一场开播一小时后），上游没有下一场就自动停用。

### 日志与存储
按「本地、用户可配、虚拟加载、分页」重做了一遍：

- **运行日志按需读盘**：不再把 `data/logs/` 下每个 run 的日志全读进内存，只有打开某次运行的日志时才读盘（内存里只留最近碰过的几次）。
- **服务端日志落盘**：每条日志都追加写进 `data/server-logs/<日期>.jsonl`，一天一个文件；以前它只在内存里，重启就清空。
- **设置页五个上限格**（设置 → 服务 → 存储信息）：历史保留条数（默认 200）、单次运行日志行数（默认 2000）、日志总量上限（默认 64 MB）、服务端日志内存行数（默认 2000）、服务端日志总量上限（默认 64 MB）。改完立刻生效，超出部分按最旧的淘汰。
- **日志页能往回翻**：「加载更早的 N 行」一页一页往上取，界面上显示「已显示 N 行」。
- 上限的口径是**按目录的字节预算**（默认 64 MB），不是按行数封顶。

### 命令行（更简单了）
- **`mcloud`**（不带参数）= 起网页服务；**`mcloud serve`** 是同一个东西。
- **`mcloud run`** = 立刻把「系统默认每日任务」跑在**你这台机器上管理员名下的全部账号**上。
- 命令行**只操作本机管理员那一个用户** ✓ —— 没有 `--user`/`--owner`（多用户的"选谁"请在网页里做）。
- `mcloud help` 看全部命令。

### 更安全的默认
- 推送地址默认**拒绝指向本机/内网**的地址（防 SSRF）；确实需要时用环境变量显式打开。

### 体验
- **连不上服务端**时，界面显示中文说明（"无法连接后端服务（服务可能未启动或正在重启）"），不再是浏览器那句英文 `Failed to fetch`。
- 用户指南整篇重写：**WebUI 篇**和**CLI 篇**分开，按"每页是干嘛的 / 什么时候用 / 点哪里"写，不需要编程基础。

## 升级
- 直接换掉那个可执行文件、重启即可；数据在程序旁边的 `data/` 目录里，**整个拷走就是备份**。
- ⚠ 用命令加过用户（`mcloud user add`）的话，加完**必须重启服务**才生效。

## 已知限制
- 定时任务**串行**执行（上游有限流，不做并发）。
- 网页里**没有**"加用户"的界面：加/删用户、重置口令请用 `mcloud user …`（有意为之）。
- 这一版**没有 macOS 预编译包**（原因见上面「拿到就能用」）。
